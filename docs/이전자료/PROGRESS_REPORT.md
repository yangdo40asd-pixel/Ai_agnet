## 1. 기술 스택 (API 및 라이브러리)

### 1-1. LLM (두뇌 역할)

| 구분 | 기획 초안 | 현재 상태 | 비고 |
|:---:|:---|:---|:---|
| **[변경]** | OpenAI API (GPT-4o-mini) 1순위, Groq(Llama-3)은 서브 후보 | **Groq API (qwen/qwen3.8-27b) 단독 채택** | OpenAI는 유료. 현 단계에서는 무료 고성능 모델로 100% 대체 가능함이 검증됨. 모델명도 Llama-3 계열이 아닌 Qwen 계열로 변경 (Llama-3 계열 전체 서비스 종료 확인됨) |

### 1-2. 금융/주식 데이터

| 구분 | 기획 초안 | 현재 상태 | 비고 |
|:---:|:---|:---|:---|
| **[변경]** | `yfinance` 단독으로 주식 데이터 수집 계획 | **`FinanceDataReader` + `yfinance` 결합** | `yfinance`는 한글 종목명 검색 불가 문제 발생. FDR이 KRX 전체 종목 코드를 조회하여 종목명 → 코드 변환을 담당하고, yfinance는 그 코드로 실시간 주가와 PER을 가져오는 역할 분담 |

### 1-3. 뉴스 데이터

| 구분 | 기획 초안 | 현재 상태 | 비고 |
|:---:|:---|:---|:---|
| **[변경]** | `BeautifulSoup`으로 직접 크롤링 1순위, 네이버 검색 API는 권장 수준 | **`NAVER API HUB (NCP)` 공식 API 메인 채택**, BS4는 PoC 보조 수단으로 유지 | 네이버 개발자 센터가 NAVER Cloud Platform(NCP)의 API HUB로 이관됨. 기존 도메인(openapi.naver.com) 서비스 종료. API 키 발급 방식 및 호출 엔드포인트가 전면 변경됨 |
| **[추가]** | — | `NAVER API HUB`에서 Client ID, Client Secret 발급 완료 | NCP에서는 키 명칭이 `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY`로 변경됨 |

### 1-4. 금융감독원 DART API

| 구분 | 기획 초안 | 현재 상태 | 비고 |
|:---:|:---|:---|:---|
| **[예정]** | yfinance 부족 시 국내 기업 재무제표 보완용으로 선택 사항 명시 | 아직 미착수 | Phase 2 이후 재무 지표 확장 단계에서 도입 검토 예정 |

### 1-5. AI 모델 추가

| 구분 | 기획 초안 | 현재 상태 | 비고 |
|:---:|:---|:---|:---|
| **[추가]** | — | `.env` 파일에 `GEMINI_API_KEY` 슬롯 추가 | Groq 외 Google Gemini API도 향후 두뇌 교체 또는 병행 사용 가능성을 열어두고 키 공간 미리 확보 |

### Phase 2: 데이터 수집 모듈 개발 (PoC)

기획 초안에서는 `finance_api.py`, `news_scraper.py` 두 개의 독립 파일로 개발하는 것을 계획했으나, 현재는 **PoC 통합 스크립트 형태**로 먼저 실현 가능성을 증명한 뒤 모듈 분리를 다음 단계 과제로 남겨두는 방향으로 진행하였다.

| 항목 | 기획 초안 내용 | 현재 상태 |
|:---:|:---|:---:|
| **[변경]** | `finance_api.py` 단독 파일 개발 | `poc_archive/agent_poc.py` 내 통합 구현 완료. 별도 파일 분리는 예정 |
| **[변경]** | `news_scraper.py` 단독 파일 개발 | 동일하게 `poc_archive/agent_poc.py` 내 통합 구현 완료. 분리는 예정 |
| **[완료]** | 중간 점검 (터미널에서 텍스트 제대로 가져오는지 시연) | 완료. 터미널 + 웹 UI(Streamlit) 두 가지 형태로 모두 검증 |
| **[추가]** | — | `poc_archive/test_data.py`: API 3종(뉴스, FDR, yfinance) 각각 단독 연동 테스트 스크립트 작성 및 통과 |
