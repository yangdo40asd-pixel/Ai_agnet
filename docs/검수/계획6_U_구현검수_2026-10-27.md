## 2. 사용자 경험에서 바뀐 점

1. ‘세 줄/세 문장’은 본문의 분량 제한이다. 카드 요청보다 우선하며 불필요한 카드·제목·별도 영향 문단을 붙이지 않는다. 화면 폭 때문에 자연스럽게 접히는 줄 수와 명시적인 본문 줄바꿈은 구분한다.
2. ‘이슈 세 개’는 최대3개의 독립 사건 요청이다. 관련 기사가3건이어도 같은 사건이면 카드1개다. 실제 확인된 자료가0/1/2건이면 그 범위로 제한한다.
3. ‘이슈 두 개를 각각 한 문장’은 카드당 본문+영향 해석을 합쳐 한 문장이다. 전체 답변을 한 문장으로 바꾸지 않는다.
4. 짧은 공지/일정은 implication=null/빈 문자열로 생략할 수 있다. 추가 해석을 쓰면 본문과 같은 수치·근거·문체 검사 및 문장별 의미 심사를 받는다.
5. 같은 실적 발표의 여러 기사 출처는 Python이 원래 근거 ID/URL로 함께 연결한다. 모델이 URL을 생성하지 않는다. 관련 없는 사건을 한 카드에 섞거나 같은 사건을 여러 카드로 반복하면 거절한다.
6. 카드에는 제목·본문·필요한 해석·출처 도메인을 표시한다. 본문 분량과 출처 상세는 별도 영역이다. 텍스트 전용 응답에는 빈 카드/해석 영역을 만들지 않는다.

## 3. 코드 책임과 실제 구현 경계

### 3.1 요청 계약: src/agents/presentation.py

PresentationContract가 style, max_sentences, max_lines, max_issues, per_issue_sentences를 분리한다. ‘세 줄’은3줄/3문장 이내, ‘세 문장’은3문장 이내이며 세로 줄바꿈을 강제하지 않는다. 명시적인 텍스트 요청은 일반 뉴스 카드 기본값보다 우선한다. ‘각각/각 이슈/문장씩’은 이슈별 제한으로 처리한다.

같은 계약을 질문 지시문과 사후 검증에서 공유한다. 긴 고정 개념 설명도 명시적 분량을 초과하면 그대로 반환하지 않고 기존 개념 근거를 사용한 제한 길이 생성 경로로 보낸다. 짧은 요약의 이미지/PDF 미열람 고지는 별도 notices에 남겨 본문 문장 수를 늘리지 않는다. 일반 기존 첨부 안내와 세 값 반환 계약은 유지한다.

모든 한국어 분량 표현을 이해하는 자연어 파서는 아니다. 숫자/한·두·세·네·다섯 등 정의한 문형을 처리한다. 문장 수는 문장부호와 명시적 줄바꿈을 기준으로 세며 소수점을 문장 경계로 분리하지 않는다.

### 3.2 사건 식별: src/agents/issues.py

IssueGroup은 원래 근거 ID, 대상/종류, 식별 앵커, 묶은 이유, 충돌 항목, 제공된 문서 버전을 보존한다. 제목 유사도나 기사 발행일만으로 병합하지 않는다.

- 실적: 명시된 같은 재무기간과 연결/별도 기준을 사용한다. 다른 분기/회계 기준은 분리한다. 잠정/확정 등 속성이 다른 수치도 충돌 검사에서 빠지지 않는다.
- 투자: 확인된 프로젝트·검증된 투자금액·목표기간 묶음이 있어야 같은 사건으로 묶는다. 상반기/하반기 목표가 다르면 분리한다. 단순히 ‘투자 계획’이라는 제목이 비슷하다고 합치지 않는다.
- 계약: 명시적인 계약번호가 있으면 식별자로 사용한다. 상대방/내용만으로 같은 계약이라고 확정하지 않는다. 같은 날 서로 다른 계약 상대가 명시되면 분리할 수 있으나, 같은 상대의 미식별 계약 여러 건으로 카드 수를 채우지 않는다.
- 회사: 결과 객체의 stock_name을 원문의 회사 귀속 증거로 대신 사용하지 않는다. 확인되지 않으면 company_role_unconfirmed다. 다만 생산 계획과 계약 취소처럼 이미 다른 사건 종류까지 ‘같은 사건’으로 바꾸지는 않는다. 최종 회사 관련성 심사는 기존 뉴스 채택/의미 검증이 계속 담당한다.
- 충돌: 같은 사건·항목·단위·기간의 값이 다르면 원문/값을 남기고 conflicts로 전달한다. Decimal로 비교해 동등한 금액 표기 때문에 충돌이 생기지 않게 한다. 평균·최신 날짜로 값을 선택하지 않는다. 충돌을 설명하지 않는 카드도 거절한다.
- 정정: VerifiedEventLink를 **이미 공식 검증된 입력으로 주입한 순수 함수 검사**에서는 문서ID/사건/이전 문서/변경 항목별 버전을 보존한다. 없는 이전 문서나 순환 연결로 충돌을 없앨 수 없다. 실제 수집기가 이 연결을 자동 생성하지 않으며 공식 관계 판정은 Y 범위다.

미확인 자료는 그대로 원자료에 보존한다. 불명확한 같은 종류의 자료를 여러 독립 사건으로 세지 않는다. 이 보수적 제한은 ‘시장에서 다른 사건이 없다’는 뜻이 아니다. 임의 자연어 전체의 사건 식별을 해결한 것도 아니다.

### 3.3 생성·자료형·검증 연결

- `src/models.py`: AnswerBlock의 기존 title/text/evidence_ids 필수·기본값 순서를 보존하고 implication을 기본값 None으로 추가했다. headline/summary 생성 인수·속성 별칭도 지원한다. 기존 위치 인수, dataclasses.replace/asdict 왕복과 ChatResponse 세 값 풀기를 검사했다. 모델의 주 계약은 호환성을 위해 title/text/evidence_ids/implication을 사용한다.
- `src/agents/answer_quality.py`: 공통 요청 계약을 지시문에 사용하고, 모델용4건을 고를 때 중복 기사로만 채우지 않고 서로 다른 사건 대표를 먼저 포함한다. 명시 필수 ID와 원자료는 보존한다. implication도 별도 검토 문장에 포함한다.
- `src/agents/chat.py`: issue_groups/presentation을 생성 요청에 넣고 검증 시 실제 카드 수·그룹·문장 수를 다시 확인한다. 같은 사건 출처는 원래 순서로 추가한다. 숫자는 추가 출처로 넓히기 전에 해당 문장의 명시 근거로 검사한다. URL/미등록 수치/잘못된 단위 검사를 우회하지 않는다.
- `src/agents/output_contract.py`: 최대 카드 수는 min(요청 상한, 확보한 이슈 수,3)이고 텍스트 전용은0이다. implication은 문자열 또는 null이다. 이전 모델/저장 응답에서 필드가 생략된 경우도 검증기가 지원한다. 모델 입력에 개인정보나 새 API 키를 추가하지 않는다.
- `src/analysis_flow.py`: 종목 선택 직후의 기본 요약도 같은 사건의 기존 설명을 한 카드에 접고 연간 재무 카드는 유지한다. 중복 문단을 제거하고 뉴스 카드는 최대3개로 제한한다. 이전 저장 리포트에서 여러 근거에 걸쳐 있던 동일한 일반 문장은 새 사건 연결을 추정해 재작성하지 않는다.

기존 CMP 자리표시자/증감률·연도/단위 가드와 unsupported 문장 하나라도 전체 승인을 뒤집는 의미 심사는 보존한다. 최종 생성 문장만 보고 원래 자리표시자가 사라진 것으로 착각하지 않도록 raw payload 검사도 명시적인 회귀 사례로 추가했다.

### 3.4 화면: src/ui/answer.py

기본 Streamlit 테두리 컨테이너로 제목/본문/선택적 해석을 묶었다. 고정 카드 높이나 본문 3~4줄 채우기는 적용하지 않는다. 원래 근거의 안전한 URL로만 도메인 링크 배지를 만들고 하단 출처·접이식 메타데이터는 유지한다. 잘못된 URL은 배지나 링크 버튼으로 만들지 않는다. URL 없는 서로 다른 뉴스도 제공자 이름이 같다는 이유만으로 하나의 출처로 합치지 않는다.

기존 title/text 메시지와 새 별칭 자료를 표시할 수 있다. notices는 본문과 별도 표시한다. 실제 브라우저 폭별 모양을 육안으로 확인한 것은 아니며 AppTest는 렌더링 구조·텍스트·URL·빈 영역·반복 메시지 오류 여부를 확인했다.

## 5. 다음 작업과 유지할 한계
