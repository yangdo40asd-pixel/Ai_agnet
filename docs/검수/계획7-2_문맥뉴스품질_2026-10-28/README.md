# 검수 증거 읽는 순서

1. `최종검수_요약.json`: 실제 통과 범위, 첫 생성/심사/관계 판정 호출, 현재 코드 해시, 마지막 미세 조정의 범위.
2. `quality_release_context/news/periods/judgement_20261028.json`: 핵심18문항의 새 로컬 생성. 각 코드해시와 저장 원자료 해시를 보존한다.
3. `quality_metric_final_20261028.json`: 마지막 상대 지표 지침 미세 조정 후 PER 개념→상대 수준의 2문항 재확인. 기존18개와 겹치는 재검수다.
4. `quality_full25_20261028.log`: 최종716개 자동 검사. 앞선 full14/full23 실패와 수정 이유는 상위 구현 검수 문서에 있다.
5. `quality_real_sources_20261028.json`: 실제17개 HTTP/네 기간 비교/뉴스20건. 이후 대화 실행은 외부 금융 재수집0/Groq0이며 실시간 최신 금융조회/UI 종단으로 세지 않는다.
6. 다른 `quality_*`는 실패 재현과 중간 수정본이다. 파일명에 final/close가 있어도 최신 성공을 뜻하지 않는다. 이를 섞어 성공률을 계산하지 않는다.

상위 `계획7-2_문맥뉴스품질_구현검수_2026-10-28.md`에 구현 책임·실제 예시·유지보수/검증 경계와 남은 작업을 적었다. 모델/서버/환경 설정을 임의로 바꾸거나 실제 수행하지 않은 검수를 완료로 세지 않는다.
