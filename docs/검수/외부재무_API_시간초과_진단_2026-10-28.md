# 외부 재무 API 조회 실패·시간 초과 추정 진단 — 2026-10-28

이 파일은 사용자가 요청한 ‘코드로 해결할 수 없는 외부·모델 한계는 증거와 대응을 별도 기록’하는 보고서다. 확정한 현상은 OpenDART 기업 고유번호 파일 조회의 일회성 실패다. 약12초의 대기 상한과 실패 시점이 일치해 시간 초과 가능성이 높지만 당시 예외 종류를 보존하지 않았으므로 원인 확정으로 쓰지 않는다. **모델 성능 부족·토큰 한도·API 호출 한도 초과로 확인된 사건이 아니다.** 지속 장애 여부도 확인하지 않았다.

## 확인한 사실

[원문](계획7-2_분기연결_2026-10-28/upstream_timeout.json)의 `/api/corpCode.xml` 요청에는 정상 HTTP 응답 상태가 기록되지 않았고, 전체 분기 수집이 약12.224초 뒤 failed가 됐다. 분기 보고서/로컬 LLM 단계로 진행하지 못했다. LLM0회, Groq0회다. 앞선 실행의 같은 실제 보고서 수집은 성공했다. 마지막 프로브는 새 프로세스여서 기존 프로세스의 메모리 기업 코드 캐시를 공유하지 않는다.

따라서 ‘2025년 3분기 보고서가 없다’, ‘로컬 모델이 못 답한다’, ‘한도가 찼다’로 해석하면 잘못이다. 관찰용 프로브의 개별 요청 대기 상한은12초였다. 이 기록만으로 실제 서버 고정 장애나 연결 지연의 근본 원인까지 단정하지 않는다.

## 자동으로 보완한 부분

- 실패 상태와 안전한 조회 메시지를 결과 스냅샷에 보존한다.
- 모델을 호출해 없는 분기 내용을 만들지 않는다.
- 같은 요청의 실패를 미공시·자료 없음으로 단정하지 않고 ‘분기 재무자료 조회 실패’로 구분한다.
- 인증·요청 한도는 자동 재시도하지 않는다. 모델/Groq로 우회하지 않는다.
- 문장 품질 검수는 저장한 실제 API 근거의 출처·해시를 보존해 새 로컬 생성으로 별도 진행했다. 새 API 성공으로 표시하지 않았다.

오류 안내 구분과 정상·반례는 자동 검사로 확인했다. 이 코드를 추가했다고 외부 서버 응답이 복구됐다고 보고하지 않는다.

## 다음 대응 순서

1. 잠시 후 같은 연도·분기를 명시해 한 번 재조회하고 고유번호→분기 보고서→모델 각 단계 상태를 확인한다. 현재 코드는 ‘2025년 3분기 실적 재조회’처럼 기간과 재조회를 함께 입력할 수 있다.
2. 실패가 반복되면 기업 코드 파일의 연결/전송/파싱 시간을 나눠 측정한다. 401/403·429·OpenDART 상태 코드가 확인되면 시간 초과와 별도로 분류한다. 키 값은 출력하지 않는다.
3. 프로그램에는 정상 기업 코드 매핑의24시간 메모리 캐시가 이미 있다. 새 진단 프로세스를 계속 만들면 이 캐시가 재사용되지 않는 점을 고려한다. 언어 품질 검수에는 저장된 실제 근거를 재사용하고, API 종단 검수만 별도로 수행한다.
4. 실제 사용자 프로세스에서도 문제가 반복된다면 검증된 기업 코드의 만료·파일 무결성·오류 격리를 갖춘 캐시 보관을 검토한다. 오래된 매핑을 무조건 승인하거나 인증·한도 오류에서 캐시로 문제를 숨기지 않는다.
5. 응답 시간이 일시적으로 길다는 이유만으로 모델 교체·서버 재시작·.env의 한도 증가를 하지 않는다. 별도의 증거가 있는 경우에만 원인에 맞는 변경을 한다.
