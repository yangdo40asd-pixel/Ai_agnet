# 계획8 실행01 — 첫 탐색 답변과 선택 강요 해소

날짜: 2026-10-29 / 사용자 이미지 제보에 따른 최우선 작업. 전체 금융 대화 재설계 완료 보고가 아니다.

## 변경된 사용자 경험

- 명시 테마에서 관련 후보를 상장 대조한 후 KIND 회사목록의 업종·주요제품 원문을 추가 조회한다. 첫 답변은 그 원문에 따른 기업 사업과 차이를 설명한다.
- 본문과 파란 상자의 ‘분석할 종목 선택’ 중복 안내를 제거했다. 종목 버튼은 선택적인 개별 분석 동작으로 남기고 상세 표의 중복 선택 목록은 표시하지 않는다.
- 종목 선택 없이 ‘이 기업들은 서로 뭐가 달라?’를 처리한다. 일반적인 재무 비교는 기존 동일 기준 비교 경로에 남긴다.
- 추가 관련주는 기존 후보·선택·대화·분석·캔버스를 보존하며 새 기업의 사업 자료도 누적한다. 최근 집합과 전체 집합을 구별한다.
- ‘메모리 쪽만 설명해줘’처럼 원문 어휘로 명시된 분야를 좁히는 경로를 추가했다. 직접 대응하는 원문이 없으면 그 확인 범위를 설명하고 임의의 회사 분류를 생성하지 않는다.
- 후보 단계의 고정 PER 제안 대신 실행 가능한 기업 차이·추가 탐색 질문을 제안한다. 캔버스나 모든 기업의 전체 재무 리포트를 자동 생성하지 않는다.

## 실제 자료 조사와 한계

공식 출처: [KRX KIND 상장법인목록](https://kind.krx.co.kr/corpgeneral/corpList.do?method=loadInitPage&scrnmode=1).

공개 다운로드를 requests로 실제 호출해 HTTP200과 회사명·종목코드·업종·주요제품 열2759행을 확인했다. API 키나 로그인·유료 가입 없이 이번 환경에서 조회됐다. 별도 유료 API 상품을 도입하지 않았다. 이는 향후 접근 보장이나 무제한 이용 권한을 뜻하지 않는다. FinanceDataReader의 KRX-DESC도 [공식 저장소](https://github.com/FinanceData/FinanceDataReader)에서 확인했으나, 이번 수집은 응답 크기·시간 제한을 명시할 수 있는 직접 공개 다운로드 경로를 사용했다.

추가 설치 패키지 없이 기존 requests/pandas를 사용한다. 요청15초 상한, 응답8MB 상한, 한 시간 캐시를 적용했다. 실패는 성공 캐시로 남기지 않는다. 모델 턴의 남은 예산을 적용하며, 기존 LLM 공급자·검증·시간/호출 예산을 우회하지 않는다.

이 자료의 조회 시각은 제품 정보 갱신일이 아니다. 최신 수요·실적·시장 점유율·고객·사업 비중은 이 목록으로 확인하지 않는다. 예를 들어 SK하이닉스의 이 표에는 ‘반도체’라는 폭넓은 표현만 있어 ‘메모리’ 후속에서 다른 근거 없이 세부 분류를 확정하지 않는다. 이는 그 기업이 해당 사업을 하지 않는다는 판단이 아니라 확보한 자료의 분류 범위다. 이수페타시스/HPSP처럼 목록의 제품만으로 테마 직접 연결이 충분하지 않은 후보는 사업 사실과 미확인 연결을 구분해야 한다. 이 경계의 추가 검수·보완 출처 연결은 F01-V2에 남겼다.

신규 기업 사실은 공식 원문에서만 등록한다. 모델이 추출하고 스스로 맞다고 한 것을 원자료로 승격하지 않는다. 회사별 수치/기간/회계기준·기존 검증을 완화하지 않았다. 생성/의미 심사에 실패한 답변은 정상 생성 성공으로 집계하지 않는다.

## 자동 검사

- 관련 신규17개가 포함된 전체 **780개 / 56.741초 통과**. 기존763개에 신규17개다.
- 마지막 사업 분야 좁히기와 커버리지 조건 분리 뒤 신규19개(2.421초), 기존 요청10개(0.188초), 기존 탐색/비교17개(2.706초)를 통과했다. 최종 코드에서 전체782개를 다시 실행했다고 보고하지 않는다.
- 신규 검사는 이름/코드 불일치·중복 원문·선행0 보존·필수 스키마·AI 반도체 오승인 방지·배터리 동의어 범위·자료 조회 실패 보존·기업별 근거/호출·환각 수치 및 의미 거절·정상4족/잘못된6족/가짜4%·자료 없는 모델 호출 금지·부분 결측·다른 기업 침범 방지·관련 제품 발췌 시 원문 보존·분야 선택 및 결측·선택 없는 AppTest를 포함한다.
- 기존 test_user_flow의 사업 자료는 명시적으로 결측 모의 입력을 주입해 외부 호출을 차단했다. ‘선택 안내가 있어야 한다’는 구 UI 기대만 새 요구인 중복 안내 제거에 맞게 수정했다. 수치 거절이나 기존 실패 검사는 삭제/완화하지 않았다.

## 실제 모델·자료·서버 검수

1. 새 공식 사업 자료 + 로컬 생성/의미 심사로 반도체·2차전지·로봇 세 테마를 실행했다(first_discovery_matrix.json). 최초 반도체→기업 차이→새3후보 추가도 기록했다. matrix의 local 호출14회이며 로봇은 원문4족 숫자 오탐으로 제한 답변이 됐다. 이 실패를 성공으로 집계하지 않는다.
2. 원문 제품 숫자 검사 보완 뒤 저장한 실제 로봇 자료 + 새 생성/의미 심사로 정상 답변을 반환했다(first_discovery_saved_final.json). 이 파일의 두 번째 검수는 저장된 누적6기업 전체 자료에 대한 설명이며 실제 신규3기업만 확장한 UI 검수와 혼동하지 않는다.
3. 실제8501 서버에 HTTP/WebSocket으로 입력과 전송을 보내 ‘반도체 관련 종목’→‘서로 뭐가 달라?’→‘관련주 더 보여줘’를 연결했다(first_discovery_http.json). 각 단계 예외0건, 강제 선택 안내0건, 누적후보6개를 확인했다. 이 버전은 제품 발췌 보완 전이라 장황한 원문 나열이 있었다.
4. 발췌 보완 후 같은 서버 경로로 첫 질문→기업 차이를 재확인했다(first_discovery_http_final.json). 무관한 제품 나열이 줄었으며 예외0건/강제 선택 안내0건이었다.
5. 마지막 코드로 서버를 갱신한 뒤 첫 질문→‘메모리 쪽만’→‘소재 분야만’을 실행했다(first_discovery_http_area.json). 메모리 원문이 있는 기업만 설명하고 소재 근거가 없는 분류는 만들지 않았다. 예외0건, 파란 선택 안내0건이었다.
6. 실제 서버 검수는 프로토콜이 반환한 문장·버튼·알림을 읽었다. 브라우저 스크린샷/화면 배치 육안 검수나 이번 버전의 실제 금융 API→개별 분석/Excel 재검수를 수행한 것은 아니다. 개별 선택 경로는 기존 AppTest와 회귀로 보호했다. 따라서 F01-V4는 실제 화면 확인의 잔여를 남겨 둔다.

실제 API·모델 검수는 순차 실행했다. UI 반영에는 오래된 모듈 잔류 문제를 피하려고 화면 서버만 동일 설정으로 재시작했다. 모델1234는 유지했고 환경/모델/WBS/타인의 기존 변경은 보존했다. Git 커밋/푸시는 하지 않았다.

## 판정과 다음 시작점

- F01-I1~I8 구현, F01-V1(다른 테마), F01-V3(선택 없는 연결/직접·버튼 AppTest) 검수 범위만 완료 체크한다.
- **F01-V2 남음:** 희소한 제품 설명·부분 미확인 후보의 관련성 해석, 자료 최신성 표현과 보완 출처의 경계를 추가 검수한다. 특히 일반 반도체 등록을 AI 공급 사실로 확대하거나, 분야 단어 부재를 실제 사업 부재처럼 읽히게 해서는 안 된다.
- **F01-V4 남음:** 실제 화면 배치·가독성 육안 확인. HTTP/프로토콜 검수는 수행했지만 육안 확인으로 대체 집계하지 않는다.
- 현재 단계는 **실행01-E**이며 위 미완료를 닫기 전 실행02-A로 넘어가지 않는다. 최신 관심 테마 발견 기능과 전체 UI/금융 답변 재설계를 완료했다고 말하지 않는다.
