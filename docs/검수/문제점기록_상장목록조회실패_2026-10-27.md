## 3. 왜 오래 못 찾았나 (재현·진단을 방해한 요인)

1. **실제 에러가 숨겨짐.** `src\data\stock.py` 36~45행 `load_listing()`이 `fdr.StockListing("KRX")`의 모든 예외를 잡아 `raise AppError("listing_failed", ...) from None`으로 같은 문구로 바꿈. 원래 예외가 사용자 화면과 로그 어디에도 남지 않음.
2. **진단 기록 누락.** `src\diagnostics.py`의 허용 코드 목록에 `listing_failed`, `listing_format`이 없어, 앱 로그에는 `code=unspecified`만 찍힘(`stage=chat type=AppError code=unspecified`).
3. **재현 조건 불일치.** 터미널·AppTest·진단용 실행기는 `FinanceDataReader`나 `requests`를 앱보다 먼저 불러오거나 `src/ui`를 경로 맨 앞에 두지 않아서 실패하지 않음. `start.bat`처럼 `-m streamlit run src\ui\app.py`로 첫 질문 때 처음 불러오는 경우에만 발생.
4. **잘못된 진단 유입.** 다른 AI는 "KRX/GitHub 의존, 네트워크 시간 초과, CSV 누락" 등으로 진단했으나, 실제 네트워크 조회는 같은 시간대에 제 쪽에서 0.2~0.4초에 성공했고 CSV 캐시도 05:52부터 존재했음. 원인 오판.
5. **시점 혼동.** 2026-10-27 15:40에 파일이 생긴 뒤부터 증상이 시작됐고, 사용자는 "어느 순간부터 꼬였다"고 표현.
