## 발견한 문제와 보완



1. **최근 실적 기준 PER 누락:** Yahoo의 종목 요약에서 trailingPE와 trailingEps가 없는 응답을 확인했다. 같은 제공자의 최근 12개월 손익계산서에는 희석 EPS가 있어 보완했다. 재무 통화가 원화로 확인되고 최신 응답 기간의 EPS가 유효할 때만 계산한다. 0·누락·비정상 값이면 추정하지 않는다. 원자료 정밀도를 유지하고 계산식, EPS, 실적 기간 종료일을 화면에 표시한다. 예상 PER를 대신 넣지 않는다.

2. **AI의 잘못된 회사명:** 실제 없는 이름이 반복돼 한 번 재제안하도록 했다. 실제 목록에서 확인한 이름 중 테마 문자열 또는 이미 확인한 후보명과 접두부가 겹치는 참고 후보를 최대 60개 제공한다. 명칭 참고 목록은 테마 연관성 검증 결과가 아니다. 재제안도 실제 목록과 다시 대조하며 임의로 비슷한 이름의 코드에 연결하지 않는다.

3. **뉴스 검색어 문제:** ‘반도체 테마주 분석해줘’를 통째로 검색했을 때 과거 기사가 반환됐다. 끝의 요청 문구를 정리해 ‘반도체 삼성전자’처럼 검색한다. 발행 시각을 AI에도 전달하고 과거 기사를 현재 사건으로 단정하지 않도록 요청한다.

4. **AI 출력 형식·뉴스 번호 오류:** 지원 모델에는 JSON Schema로 필수 항목, 실제 뉴스 번호, 설명 개수, 전달한 종목명·값을 제한한다. 설명 문자열에는 숫자를 생성하지 않도록 제한하며 숫자가 들어 있는 테마명은 ‘이 테마’처럼 표현한다. 제공자가 JSON 생성 오류를 반환한 경우에만 일반 JSON 모드로 한 번 재요청한다. 어느 경로든 반환값을 로컬 검증에 통과시켜야 사용한다.

5. **긴 소수점 재출력 오류:** 직접 계산한 PER의 긴 소수점을 API가 그대로 생성하지 못하는 경우가 있었다. 수집 원자료와 계산값의 정밀도는 보존하고, AI에는 화면과 같은 소수 둘째 자리 값을 전달·대조한다.

6. **설명 검증 실패:** 기사 제목의 연도나 ‘최근 12개월’을 설명에 그대로 옮겨 숫자 검사에 걸리는 경우, 설명 개수·뉴스 근거·권유 표현 오류가 있었다. 원자료와 실패 이유를 전달해 한 번만 재작성한다. 종목명과 지표 값의 불일치는 허용하지 않는다. 시장 제도 명칭인 ‘매도 사이드카’는 매매 권유와 구분하되 ‘매수 기회’ 등의 권유는 계속 거부한다.

7. **호출 한도:** 연속 검사에서 실제 HTTP 429를 확인했다. 제공자가 명시한 대기 시간이 10초 이내일 때만 한 번 기다렸다가 재요청한다. 지속되는 한도 제한은 별도 안내를 표시한다. 자동 검사 입력 사이에는 기본 45초 간격을 둔다. 이는 실제 서비스의 동시 요청 대응을 완료했다는 뜻이 아니다.

8. **모델 비교와 변경:** 기존 qwen/qwen3.8-27b는 일부 입력에서 매매 권유 등 검증 실패가 반복됐다. 같은 Groq 계정에서 openai/gpt-oss-20b를 비교한 뒤 `.env`, 기본 설정, 예시 설정을 변경했다. 추론 토큰을 고려해 후보 생성 출력 한도를 조정했다. 기존 API 키 값은 변경하거나 기록하지 않았다.
