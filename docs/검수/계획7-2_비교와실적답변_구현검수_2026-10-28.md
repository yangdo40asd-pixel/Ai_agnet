## 2. 확인한 문제와 수정 이유

1. **두 기업 비교가 항상 준비 중 안내였다.** `primary_stock=None`인 관계 질의를 단일 종목 파이프라인에 보내면 안 된다. 별도 비교 경로에서 두 기업의 연간 자료를 각각 수집하고 공통 기간·회계 기준·항목을 계산하도록 했다.
2. **CMP 근거 ID가 기업 간 충돌한다.** 기존 `CMP_2024_2025_CFS_*` 앞에 공식 종목코드를 붙이고 기업별 `source_id`와 전체 `comparison_id`를 별도로 보관했다. 기존 단일 종목 Fact 형식은 바꾸지 않았다.
3. **연도만 같고 공통 지표가 없어도 비교 성공이 될 수 있었다.** 공통 연도·기준뿐 아니라 양쪽에서 같은 지원 항목이 확인되는지를 검사한다. 매출만 있는 A와 영업이익만 있는 B, 당기순이익만 있는 두 기업은 현재 비교 성공으로 처리하지 않는다.
4. **실제 ‘2025년 실적은 좋은 편이야?’가 실패했다.** 평가 표현 `좋은/나쁜/괜찮/양호/어떤 편`을 비교 의도로 선택하지 않아, 확보한 전기·당기 비교 근거가 모델 입력에서 빠졌다. 필요한 비교 자료를 선택하도록 고쳤다. 잘못 생성한 숫자를 승인하거나 실패 검사를 제거하지 않았다.
5. **‘자세히 원인 설명’에도 2문장 제한이 적용됐다.** 상세 요청은 원가율·판관비율 변화와 영업이익률의 관계를 풀어 설명하도록 했다. 사용자가 따로 요청한 문장 수 제한은 유지한다. 새로운 사업 원인을 만들어도 된다는 뜻은 아니다.
6. **분기 질문에 연간 자료로 답할 위험이 있다.** 명시한 분기의 검증된 자료가 없으면 해당 분기 수치를 확보하지 못했다고 짧게 답하도록 경계를 추가했다. 분기 수집 기능을 새로 완성한 것은 아니다. 이미 확보한 같은 분기·연도의 검증된 Fact는 기존 생성·검증 경로로 보낸다.
7. **비교에 불필요한 ROE API가 호출됐다.** 비교 수집만 `include_indices=False`로 실행한다. 기존 단일 종목은 기본값 True를 유지한다. 마지막 비교 실측의 외부 요청은 8회이며 불필요한 지표 조회가 없다.

## 5. 실제 로컬 모델·금융 API 검수

검수는 AppTest가 **현재 제품 UI 코드를 호출하면서 실제 수집·로컬 LLM을 사용하는 방식**이다. 프로브에서 외부 값을 가상 응답으로 교체하지 않았다. Groq 생성자는 호출 금지로 감시했고 0회였다. 브라우저로 열린 8501 세션을 조작한 실측은 아니다. 1234/8501 health는 별도로 HTTP200을 확인했다.

각 프로브는 호출·시간 예산을 두고 실제 모델의 생성·심사 원문, 예외, `request_status`, 출처, 비교 ID를 저장했다. `exceptions=[]`만으로 성공을 판정하지 않는다. 요청 횟수에는 requests와 urllib를 함께 관찰했으며, 키/인증 헤더/쿼리 문자열은 기록하지 않았다. curl_cffi 전체까지 감사한 네트워크 총량 측정은 아니다.

- **수치와 의미:** 매출/영업이익 변화와 이익률을 연결한다. 상세 원인 답변은 원가·판관비 비중을 설명한다.
- **문맥:** 실제 두 기업 후속 질문은 동일 ID 자료를 재사용했다. 단일 기업의 상세 원인 후속 질문도 대상을 유지했다. 임의의 모든 후속 질문이 해결됐다는 뜻은 아니다.
- **한계 비중:** 질문하지 않은 PBR 누락이나 무관한 경고를 앞에 붙이지 않았다. 명시 분기를 확보하지 못한 경우는 답변을 대신 만들지 않았다.
- **요청 분량:** 실제 3문장 평가, 2문장 비교를 확인했다. 같은 주장을 다른 말로 반복하는 부분은 문장 다듬기 여지가 있지만 숫자 나열만 하는 상태는 개선됐다.
