## 5. 검사와 발견한 실패

1. 신규 검사 최초 실행에서 테스트가 존재하지 않는 fixture_result 이름을 가져와 ImportError가 발생했다. 실제 synthetic_result로 수정했다. [초기 실패](계획6_S01_초기검사실패_2026-10-27.log)는 보존했다.
2. 첫 전체 검사에서는 **388개 중 2개 실패**했다. '이 종목 뉴스'에서 optional '종목'을 잘못 소비해 '이'를 회사명으로 읽은 라우팅 회귀와, 다중 후보 요청의 기존 action 호환성 문제였다. [전체 검사 1](계획6_S_전체검사1_2026-10-27.log).
3. 지시어를 회사명 추출에서 분리하고, 모호한 복수 후보의 action=unsupported는 유지하면서 entities를 추가했다. 기존 테스트·실패 입력·검증 규칙을 제거하거나 완화하지 않았다.
4. 집중 검사에서 신규 **18개 전부 통과(6.072초)**. 이 중 새 조회→실제 answer_question/구조·수치 검사→채팅 출력, 과거 캔버스·실제 생성 XLSX 바이트 유지까지 포함했다. [집중 검사 2](계획6_S_요청집중검사2_2026-10-27.log).
5. 최종 전체 **392개 전부 통과(52.352초, 실패/오류 0)**. 기존 374개를 그대로 포함한다. [전체 검사 2](계획6_S_전체검사2_2026-10-27.log).

scripts/verify_local.py가 socket·requests·curl_cffi의 외부 연결을 차단한 상태에서 실행했다. AppTest는 실제 화면·세션 코드를 실행하지만 브라우저나 별도 앱 서버를 열지 않는다. 모델/수집 응답과 의미 심사 판정은 통제된 가상 응답이다. 자연어 답변의 실제 의미 품질을 새로 합격 처리한 검사가 아니다.
