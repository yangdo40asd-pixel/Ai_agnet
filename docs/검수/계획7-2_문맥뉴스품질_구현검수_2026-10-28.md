# 계획7-2 문맥·분량·뉴스 답변 품질 구현 검수

작성일: 2026-10-28. 아래 최종 검수 범위의 구현·검증 기록이며 전체 목표 56개 시나리오 완료 보고서가 아니다. 사용자 요청은 실제 로컬 모델의 응답을 목표 MD 두 종과 대조하고, 해결 가능한 코드 문제를 수정·재검수하며 유지보수성을 보존하는 것이다. 기준선은 직전 15시 기록의 659개 자동 검사다.

## 이번에 확인한 문제와 변경 책임

- `src/agents/followup.py`: 재요약은 가장 최근 답변의 실제 인용 근거로 범위를 묶는다. 이전 답변의 문장을 새 사실로 사용하지 않는다. 현재 원자료의 기업·기간·값·본문·URL과 다르면 재사용하지 않는다. 순서 지시(첫 번째 이슈)는 원본 NEWS_1이 아니라 실제 표시 카드의 근거에 연결한다.
- `src/agents/answer_quality.py`: 재요약→분기→기존 연간/뉴스 선택 순서를 유지한다. 이전 이익률 답변을 요약하라는 요청에 매출·영업이익 증가율을 새로 넣지 않는다. 표시된 뉴스 카드의 후속 근거와 부족한 카드 상태를 분리한다.
- `src/agents/quarterly.py`: 재요약의 분기 기간 승계와 일반 평가 후속 질문을 보강한다. 명시 연간 전환을 오래된 분기로 되돌리지 않는다.
- `src/agents/outlook.py`: 전망의 근거 선택·일반 판단 원리·생성 지침을 분리한다. 과거 실적을 미래 예측으로 쓰지 않는다. 숫자 문장 예시는 전망용 전송 사본에서만 제외하며 실제 원자료·검증용 request·실패 시 제한 답변 원본은 보존한다. 미래 확정 연간 실적의 당연한 미확보 안내 대신 현재 판단에 필요한 자료 범위를 설명한다.
- `src/agents/request.py`: 명백한 재요약·평가 후속 요청을 불필요하게 별도 의도 분류하지 않는다.
- `src/agents/chat.py`: 확인 문장 예시를 의무 복사 지시에서 분리한다. 생성→수치/형식 검사→의미 심사의 순서와 기존 제한 답변 표시를 유지한다. 뉴스가 부족하면 확보 범위의 개수만 설명한다.
- `src/agents/report.py`: “저평가로 단정하기보다는”이라는 명시적 유보를 가치 단정과 구별한다. 뒤에서 다시 가치 단정을 하면 계속 거절한다.
- `src/agents/financial_numbers.py`: “판매관리비율 또한 2024년…” 문형을 정상 인식한다. 값·연도·방향이 틀린 반례는 계속 거절한다.
- `src/agents/issues.py`: 명시된 브랜드 가치와 사내대출 사건을 분류한다. 타사 귀속·같은 사건 중복·다른 사건 혼합 검사는 유지한다. 이 작업은 공식 정정 관계 자동 식별 구현이 아니다.
- `src/agents/presentation.py`: 단일 이슈 후속 설명은 명시 카드 요청이 없으면 글로 답한다. 순수 보도 근거 답변에만 귀속을 보존하며 금융 계산·공식 원문과 혼합된 답변을 일괄 보도로 바꾸지 않는다. 실제 카드 수와 일치하는 이슈 개수만 숫자 오탐에서 구별한다. 단일 이익률 답변의 같은 %p 반복은 재작성한다.
- `tests/test_followup_focus.py`: 정상 사례와 원자료 변경·종목 불일치·없는 카드·중복 카드·다른 금융 수치·잘못된 연도/방향·같은 값인 서로 다른 지표 등의 반례를 함께 둔다.

## 실제 실행의 구분

1. 금융·뉴스 원자료 수집은 `scripts/collect_quality_sources.py`의 한정된 실제 외부 요청이다. 기업 코드·기간·요청 결과·시간을 기록하고 키/헤더는 저장하지 않는다. 삼성전자 2025년 1·2·4분기와 SK하이닉스 3분기, 각 전년 동기, 뉴스 20건을 확보했다.
2. 이후 대화 검수는 저장한 실제 자료의 해시를 보존하고 로컬 모델만 새로 호출했다. 금융 API 재수집과 브라우저 UI 종단 검수로 세지 않는다. Groq 호출은 금지하고 호출 횟수를 기록한다.
3. 각 실행은 최대 16회/240초의 검수 예산이 있다. 한 질문이 실패하면 해당 실행을 멈추고 원인을 수정한다. 수치·회계기준·기간 검사를 끄지 않는다.
4. 자동 검사 통과, 실제 응답 반환, 인간의 답변 품질 판정을 별도로 보고한다. 재작성이나 제한 답변을 첫 생성 성공과 혼동하지 않는다.

## 재현된 실패

- 초기 이익률 후속 답변: 같은 현재 값/변화율을 반복했다. 재요약은 직전 질문의 이익률만이 아니라 전체 실적 증가율을 다시 추가했다.
- 연간 원인 설명의 첫 생성: “판매관리비율 또한”이 정상 수치 대조 문형에서 빠져 재작성됐다. 문형 보강 후 같은 실제 원자료의 새 생성+심사에서 첫 답변이 반환됐다.
- 뉴스 첫 실행: 브랜드 기사 NEWS_4가 일반 미분류로 카드 후보에서 제외돼 정상 카드가 `chat_issues`로 거절됐다.
- 뉴스 후속 구현 전 구조: 첫 번째 카드가 NEWS_4여도 NEWS_1을 선택할 수 있었다. 현재는 실제 카드 순서와 원자료 동일성을 확인한다.
- 뉴스 추가 실행: 모델이 “확인된 이슈 총 2건”이라고 정확히 써도 금융 숫자 검사에서 `chat_numbers`가 났다. 실제 카드 수 일치만 제한적으로 인식한다.
- 뉴스는 반환되어도 상세 설명의 반복·불완전한 문장이 남을 수 있다. 반환 상태만으로 품질 완료라고 처리하지 않는다.

## 전망 추가 검수에서 확인한 원인

1. 이전 전망 답변이 인용한 PRICE를 요약에도 무조건 강제해, 주가 수치를 말하지 않는 정상 한 문장 요약이 `chat_evidence`로 거절됐다. 현재 요약의 원자료 범위는 그대로 두고 실제 인용할 근거는 관련 부분집합으로 선택할 수 있다. 뉴스는 사건별 하나 이상의 출처를 유지하고 같은 사건의 모든 중복 기사까지 요구하지 않는다.
2. “저평가로 단정하기보다는 비교해야 한다”는 유보가 `chat_claim`으로 오인됐다. 해당 어구 바로 뒤의 유보만 인식하고, 다른 문장의 뒤늦은 주의문으로 앞 단정을 면책하지 않는다.
3. 미래 연간 실적이 없다는 안내, 과거 수치 전 항목 반복을 유도하는 일반 생성 지침이 전망에도 전달됐다. 생성 지침과 전송 사본의 문장 예시를 전망용으로 분리한다. 원자료를 감추거나 수치 검증·의미 심사를 끄지 않는다.
4. “수요·생산 비용에 따라 결정될 전망”은 미래 판단 기준과 회사 예측이 섞이는 문형이었다. 기존 T3/T4 심사가 거절한 기록을 보존했다. 판단 조건은 앞으로 확인할 기준으로 표현하도록 생성 단계에서 고친다.

## 유지보수와 검사 강도

전망과 투자 판단의 생성 지침은 `outlook.py`에 두고, 데이터 선택·생성·표현·의미 심사를 분리한다. 전망 생성용 전송 사본에서는 금액 문장 예시의 복사 유도만 제외한다. 원래 evidence/required_groups, 검증 request, 실패 시 제한 답변용 확인 문장은 그대로 남긴다. 기존 단일 종목/분기/두 기업 비교·result_id·Local/Groq 분리·캔버스/Excel 계약을 보존한다.

`interpretation.py`에는 다음 구분을 추가했다.

- 단순 PER 조회값을 “이익 대비 낮은 주가”로 바꾸는 상대 평가를, 비교 근거 없이는 거절한다. 뒤의 투자 주의문으로 면책하지 않는다.
- “확인해야 판단할 수 있다”의 양태와 “주가가 오를 수 있다”의 실제 가설은 다르다. 전자의 제한 문형만 분류용으로 정규화하고 실제 표시 문장과 의미 심사는 그대로 둔다. 같은 절에 남은 실제 예측은 계속 심사한다.
- “예상되는 이익과 현재 가격을 비교해야 한다”는 판단 변수를 회사의 이익 증가 전망으로 오인하지 않는다. 조건 없는 “예상 이익이 증가할 전망”은 별도 반례다.
- 근거 없는 실적/이익 증가 전망도 검사한다. 확인한 계약이 실제 이행·판매로 이어질 조건을 설명하는 정상 가설은 T3로 검토할 수 있지만 자동 승인하지 않는다.
- 전체 회귀에서 기존 정상 과거 평가 문장이 미래 가설로 오인된 회귀 1개를 발견했다. 기존 테스트/픽스처를 지우거나 수정하지 않고 과거형 “개선됐다고 판단할 수 있다”를 구별해 해당 기존 검사 16개를 다시 통과시켰다.
- 올해 질문을 내년 답변으로 바꾸거나, 미래의 확정 연간 실적 부재를 불필요하게 붙이거나, 주가 질문을 과거 실적 나열로만 시작하면 재작성한다. 명시적인 미래 확정 실적 질문의 정정 답변은 허용한다.

이 경계들은 의미 심사의 무조건 승인 규칙이 아니다. 숫자·범위·회사·기간·기준·단위 검증과 LLM 의미 심사는 계속 수행한다. 판정 문형을 정규화할 때도 금액/수치/원자료를 변경하지 않는다.

추가 경계: 회사 계획·전망 자료가 이번에 미확보라는 설명은 미래의 확정 실적 부재와 다르다. 신규 스타일 검사에서 두 범위를 혼동한 오탐을 발견해 구분했다. 자료 범위 설명을 지워 미래 전망의 불확실성을 감추지 않는다. 전망의 첫 문장 순서는 모델이 실제 생성한 문장의 내용·출처를 보존해 재배치하고, 그 결과도 의미 심사를 거친다. 새 전망용 전송 사본은 이전 AI 서술을 다음 초안으로 복사하지 않게 하되, 사용자 질문·현재 원자료·기간/대상 상태는 보존한다. 요약에는 직전 답변, 이전 답변 검토 요청에는 해당 대화 서술을 계속 전달한다.


추가된 안전한 출력 정리와 출처 연결:

- 긴 소수 원본과 화면 반올림값의 반복 검사 불일치를 수정했다. 단일 이익률의 같은 변화가 자리표시자 괄호와 본문에 중복된 경우, 동일 검증 수치가 본문에 남을 때만 괄호를 생략한다. 서로 다른 지표·한 번뿐인 변화·틀린 값은 이 규칙으로 처리하지 않는다. 의미 심사 전에 처리하며 수치 원본/출처를 변경하지 않는다.
- “현재 {{PER}}은 10.81배”처럼 값 자리표시자가 이름 자리에 쓰이면, 실제 근거 키가 있을 때만 지표 이름 PER을 복원한다. 잘못된 후속 값/근거 없는 상대 평가는 여전히 거절된다.
- 상세 원가 설명에서 매출·영업이익 증감률의 ID가 누락된 실제 실패를 기록했다. 기존 복원기가 긴 원본 소수를 단순 문자열로 비교하던 문제였다. `financial_numbers.comparison_source_ids`가 기존 수치 검증기 자체로 유일한 항목 근거를 대조하고, 전체 문장의 기업·기간·기준·숫자·의미는 원래 검사로 다시 확인한다. 다른 기간/단위/방향·값 오류, 다중 회계기준, 미인용 원문에 대한 기존 직접 검사 등은 그대로 유지한다.
- 주가 질문을 제품 판매 가격 설명으로 시작하지 않도록 두 가격의 의미를 구분했다. 명시적인 주가 결론 문장을 앞에 배치하며, 실제 모델 문장의 내용은 바꾸지 않는다.

실제 원인 질문의 추가 결함과 기존 테스트 변경 사유:
