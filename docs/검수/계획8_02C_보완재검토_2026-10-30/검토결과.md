## 판정

이전 지적을 반영한 실질적인 보완은 확인됐습니다. 그러나 생성 실패 시 대체 응답의 검증·내용 보존과 카드 전용 프롬프트의 근거 범위 문제가 남아 있어, 02-C 전체 완료로 승인하기는 이릅니다. 검토 중 앱 코드·설정·계획 체크·서버·Git 커밋/푸시는 변경하지 않았습니다. 이 폴더의 재현 도구와 검토 자료만 추가했습니다.

## 우선 보완할 사항

### 1. [P2] 대체 응답은 사용자의 문장 수 제한을 검사하지 않고 반환합니다

위치: `src/agents/discovery_answer.py:240`, `_fallback`의 63~105행. 정상 생성은 219행에서 `enforce_presentation`을 실행하지만, 재시도 종료 후 대체 경로는 동일 검사를 통과하지 않습니다.

재현: 명시적 모의 생성 실패를 주입하고 실제 `discovery_answer`에 “반도체 관련 기업을 세 문장으로 소개해줘”를 입력했습니다. 도입 한 문장과 회사별 두 문장씩, 총 일곱 문장의 대체 카드가 반환됐습니다. 반환 결과에 기존 `enforce_presentation`을 적용하면 `chat_length`로 거절됩니다. 네이티브 모델 서버의 장애를 실제로 유발한 검사는 아닙니다.

영향: 수정한 문장 수 검사 자체는 작동하지만, 실패 경로에서 사용자 요청이 다시 무시됩니다. 이전 R4의 정상 경로는 해결됐으나 전체 경로는 미완료입니다.

최소 개선: 정상 응답과 대체 응답에 공통 최종 표현 검사를 적용합니다. 단순히 예외를 내는 데서 끝내지 말고 문장 예산에 맞게 기업별 요약만 남기거나 일반 문장형 대체 응답을 선택해야 합니다. 기업 수와 뉴스 사건 수를 혼동하면 안 됩니다.

검증: 생성 실패·검사 거절 후 대체 응답 각각에서 한/두/세 문장 및 줄 수 요청을 검증하고, 요청 없는 일반 카드 출력을 함께 보존합니다.

### 2. [P2] 긴 공식 사업 설명이 사라지거나 문자열 중간에서 잘립니다

위치: `src/agents/company_cards.py:197~204`, `208~212`.

재현 A: 상위 사업 발췌가 허용하는 길이 안의 정상적인 196자 단일 문장을 제공했습니다. 웨이퍼 검사·세정 장비의 개발/생산/설치/유지보수와 공급 업무가 적혀 있습니다. 그러나 대체 카드의 150자 발췌 한도에 문장 전체가 들어가지 않아 “사업 내용이 확인되었습니다.”로 바뀝니다. 자료를 확보했는데도 정작 사업 내용을 잃습니다.

재현 B: KIND의 제품 문자열 허용 범위 안에서 긴 제품 목록을 제공하면 `summary_body[:300]`이 문장·제품명 중간에서 절단합니다. 1000자 초과 문제를 길이 제한으로 막았지만, 읽을 수 있는 완결된 문장 보존은 해결되지 않았습니다.

별도 확인: 반복 문장이 들어 있는 원자료의 대체 카드는 자체 검증기에 재입력하면 `chat_directness`로 거절되지만, 반환 경로에서는 검증되지 않고 노출됩니다. 이것은 기존 1000자 초과와 다른 반복 경계 사례입니다.

최소 개선: 사업 원문 발췌와 대체 카드 조립의 길이 정책을 맞추고, 완결된 문장/제품 항목 단위로 선택합니다. 발췌 불가 시 제품·업종처럼 실제 확보한 정보를 보존해야 합니다. 카드/표현 공통 검증을 통과한 대체 결과만 반환하도록 구성하되 기존 검사를 약화하지 않습니다.

검증: 150자 초과 단일 정상 문장, 300자 초과 제품 목록, 반복 원문, 1100자 사업 절을 각각 검증합니다. 숫자·단어를 자르거나 확보한 설명을 일반 안내로 치환하지 않아야 합니다.

### 3. [P2] 공식 홈페이지 자료를 사업 보고서에서 발췌한 것처럼 표시합니다

위치: `src/agents/company_cards.py:198`.

현재 `company_business_section`에는 DART 보고서와 공식 홈페이지 자료가 함께 들어옵니다. 그런데 대체 카드 문구는 일괄적으로 “공식 사업 보고서 발췌”를 사용합니다. `document_id='WEB_fixture'`, `source='기업 공식 홈페이지'`인 모의 근거로도 이 문구가 재현됩니다.

영향: 출처 링크가 맞더라도 자료의 종류를 잘못 설명합니다. 공식 홈페이지 제품 소개와 보고서 원문을 구별하려던 기존 근거 계약과 맞지 않습니다.

최소 개선: 중립적인 “공식 사업 자료 발췌”를 쓰거나, 저장된 출처 종류에 맞춰 표현합니다. 조회 시각을 문서 발행일로 바꾸면 안 됩니다.

검증: 공식 홈페이지/IR HTML과 DART 보고서 두 자료의 표시 문구를 각각 확인합니다.

### 4. [P2] 카드 전용 프롬프트에서 기존 사업 설명 제약 일부가 빠져 근거보다 강한 표현이 통과합니다

위치: `src/agents/discovery_answer.py:188~197`. 대조: 같은 파일의 일반 응답 프롬프트 204행 부근.

기존 일반 응답 지시는 목록의 사업 구성을 ‘핵심/주력/특화/전문/집중’으로 확대하지 않도록 명시합니다. 카드 전용 지시에는 이 제약이 없습니다. 실제 로컬 모델 schema 모드에서 근거가 ‘기계 제조업 / 반도체 후공정 장비 제조’뿐인데 “반도체 후공정 장비 제조를 전문으로 하는 기업”이라고 생성됐고, 독립 의미 심사를 통과해 반환됐습니다. JSON 모드에서도 후보들이 “핵심적인 역할”을 한다는 표현이 붙었습니다.

목록에 제품이 있다는 사실만으로 전문화·주력성·중요도를 입증할 수는 없습니다. 더 상세한 실제 공식 근거가 그런 표현을 뒷받침하는 경우와 구분해야 합니다.

최소 개선: 일반형과 카드형이 공유할 사업 사실/추정 경계 지침을 공통 함수나 상수로 추출해 누락을 방지합니다. 제품 나열뿐인 자료에서 전문성·매출 비중·공급 관계를 확대하는 반례를 의미 검사에 추가합니다. 단순 금칙어 삭제나 금융 검사 완화로 해결하지 않습니다.

검증: 동일 자료의 일반형/카드형을 대조하고, 단순 등록 제품만 있는 경우와 공식 원문이 전문화 사실을 명시한 경우를 양방향으로 검사합니다.
