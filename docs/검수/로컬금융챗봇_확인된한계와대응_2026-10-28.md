# 로컬 금융 챗봇의 확인된 한계와 대응 — 2026-10-28

**15시 최신 갱신:** 명시 분기 수집·대화·Excel 연결을 구현했고 실제3분기·복합 질문을 확인했다. 최종659개 통과다. [분기 구현 검수](계획7-2_분기실적연결_구현검수_2026-10-28.md)와 [외부 조회 실패 진단](외부재무_API_시간초과_진단_2026-10-28.md)을 먼저 읽는다. 아래14시 상태와 최신 완료 범위를 구분한다.

작업 폴더는 `D:\ai_agent`이다. 이번 실측·원문은 [구현 검수 보고서](계획7-2_비교와실적답변_구현검수_2026-10-28.md)에 있다. 이 문서는 사용자가 요청한 **모델 자체·성능·자료/기능 한계의 별도 보고서**다. 모델 문제와 코드·데이터 문제를 섞지 않도록 다음 상태를 구분한다.

## 1. 현재 판단

**이번 실행에서 로컬 모델 자체의 용량이나 한국어 능력 때문에 더 이상 작업할 수 없다는 결론은 나오지 않았다.** 문맥 16384에서 실제 실적 평가·원인 설명은 첫 생성과 의미 심사를 거쳐 반환됐다. Groq는 호출하지 않았다. 문맥 초과·한도 오류는 이번 표본에서 재현되지 않았다. 모델·양자화·환경을 바꾸거나 검증을 끄는 조치는 하지 않았다.

다만 **목표 MD 전체의 품질을 만족한 것은 아니다.** 분기·예상치·어닝콜 등의 자료 경로 부족, 실제 첫 조회 지연, 다양한 질문의 미검수가 남았다. 이들은 모델을 더 크게 바꾼다고 자동 해결되지 않는다. 확인된 코드 결함은 이번에 수정했고, 미구현 수집 범위는 아래 과제로 남긴다.

## 2. 확인된 자료·기능 범위의 한계

### L1. 분기 질문을 뒷받침하는 실제 자료 연결 부족 — 확인

**14시 기준선**에서 `src/data/financials.py::collect_company_financials`는 연간 `11011`만 요청했다. **현재는** 기존 연간 함수를 유지하고 `src/data/quarterly.py`가 명시 분기/전년 동기를 별도로 수집한다. 같은 파일에 분기 정규화·비교 계산기가 있다는 사실과 **실제 분기 자료가 수집돼 챗봇에 제공되는 것**은 다르다. 이번 실제 ‘2026년 3분기 실적’ 질문에는 필요한 수치가 없었다.

즉시 반영한 조치: `agents/period_scope.py`에서 명시 분기 자료가 없으면 짧게 알리고 연간 답변으로 바꾸지 않는다. 이것은 손실 방지 경계이며 수집 확장이 아니다.

다음 구현 순서:
- [x] QuarterRequest와 별도 분기 수집 함수를 연결했다. 기본 연간 경로를 유지한다.
- [x] 기존 fetch_statement·공식 명세·실제3분기 응답을 대조했다.
- [ ] 실제1·2·4분기 응답 추가 대조. 모의 검사 통과와 구분한다.
- [x] 당분기/누적 구분과 기존4분기 차감 계산을 재사용·자동 검사했다. 실제4분기 수집 검수는 별도다.
- [x] QFIN/Q_CMP에 정기보고서 연도·분기·3개월·회계기준·출처를 보존한다. 잠정 자료를 정기보고서로 바꾸지 않는다.
- [ ] 잠정·전분기/누적 자유 비교 연결.

- [ ] 공식 정정 관계에 따른 유효 값 갱신의 실제 검수.
- [x] 실제3분기 근거가 정상일 때 생성·후속 질문이 기간 경계를 통과했다. 조회 실패는 자료 미확보와 구분하도록 보완했다.

### L2. 두 종목 비교는 연간 매출·영업이익·영업이익률의 제한된 범위 — 확인

현재는 같은 전기·당기 사업연도, CFS 또는 OFS, 원화의 공통 항목만 비교한다. 전기 자료가 필요한 방식이므로 당기 값만 있는 기업의 자유로운 비교까지 구현한 것은 아니다. 흑자 전환·전기 0은 성장률 숫자로 순위를 만들지 않는다. 세 기업 비교, 다른 통화, 다른 결산월의 정확한 기간 일치, PER/ROE·순이익·현금흐름/분기 비교는 이 기능에 포함하지 않았다.

- [ ] 확장할 항목마다 의미·산식·단위·기간 계약을 먼저 추가한다.
- [ ] 서로 다른 결산월은 사업연도 이름만으로 같은 기간이라고 보지 않도록 실제 시작/종료일 메타데이터를 수집한다. 현재 AnnualFinancialSummary만으로는 이를 엄격하게 증명하지 못한다.
- [ ] 지원 범위를 늘리기 전 정상·불일치·부분 결측 반례를 만든다. 단순 지원 목록에서 금지어만 지우지 않는다.
- [ ] 자연어 비교 후속 문맥은 제한된 지표 질문만 지원한다. 새 연도/새 기업/회사별 원인 등은 별도 계획과 검수가 필요하다.

### L3. 컨센서스·어닝콜·조정 실적의 자료 보장 없음 — 미충족 범위

목표 MD의 시장 예상치 대비 성적, 어닝콜에서 같은 발표의 3가지 핵심 내용, 가이던스 변경, GAAP/조정 EPS 비교는 해당 시점의 실제 원문/예상치가 필요하다. 현재 뉴스 제목이나 연간 재무만으로 대신할 수 없다. 뉴스 숫자가 검증됐다는 이유로 시장 예상치나 공식 발언으로 승격하지 않는다.

- [ ] 제공자별 실제 접근 가능 여부·인증·이용 조건·비용을 확인한 뒤 자료원을 선택한다. 이번 실행에서 새 유료 서비스 비용을 조사·확정한 것은 아니다.
- [ ] 원문 발행·대상 기업·재무기간·정의·예상치 집계일·공식/보도 범위·정정 여부를 구조화한다.
- [ ] 같은 실적 발표의 하위 주제와 독립 뉴스 사건을 별도 presentation 계약으로 나눈다.
- [ ] 조정 항목을 원 실적과 섞지 않고, 미확보 시 질문의 해당 부분만 짧게 설명한다.

### L4. 동종 PER·정정 공시 관계 등 추가 근거 — 미검수/별도 확장

같은 날짜의 PER이라는 것만으로 같은 이익 정의·양수 EPS·회계기준·일회성 이익 영향이 보장되지 않는다. 실제 동종 비교 자료와 산정 정의가 필요하다. 정정 공시도 날짜가 최신이라는 이유만으로 전부 대체하지 말고 같은 사건의 공식 정정 관계와 변경 항목을 연결해야 한다. 기존 보유 자료의 검증 헬퍼나 합성 테스트를 자동 수집 완료로 세지 않는다.

- [ ] 동일 기준 PER 자료와 정의를 연결하고 상대 배수 차이와 저평가 판단을 구분한다.
- [ ] 정정 전 값은 이력으로 보존하고 변경된 항목만 현재 유효 값으로 연결한다.
- [ ] 계약금액/한 해 매출의 비율을 매출 감소율로 바꾸지 않는 수용 검사를 유지한다.

## 3. 확인된 성능 문제와 아직 확인되지 않은 원인

### P1. 전체 첫 조회 지연 — 확인 / 특정 원인 단정 불가

실적 평가 질문 한 건은 전체 89.625초였다. 로컬 생성 5.452초, 의미 심사 8.986초, 합계 14.438초다. 나머지 75.187초에는 수집·조회/설정·처리 단계가 포함되지만 개별 요청 시간을 기록하지 않아 특정 API만의 문제라고 단정할 수 없다. 같은 세션 후속 질문은 추가 수집 없이 전체 14.592초였다.

두 기업 첫 비교는 앞 프로브 51.038초, 뒤 프로브 3.671초로 차이가 컸다. 환경·캐시·외부 응답 조건이 다를 수 있으므로 코드 변경만으로 14배 개선했다고 보고하지 않는다. 불필요한 공식 지표 호출을 비교에서 제외한 것은 별도로 확인된 개선이다(관찰 요청 12→8, 회사 목록·코드 조회 포함).

다음 순서:
- [ ] 키/헤더/개인정보 없이 제공자·단계·시작/종료·상태·캐시 적중·자료 기준을 기록한다.
- [ ] 목록/기업 코드/재무/LLM 생성/심사를 나눠 같은 조건의 첫 조회와 재조회를 측정한다.
- [ ] 병목이 확인된 단계에만 캐시 만료·같은 요청 중복 제거·기한을 적용한다. 인증 실패/호출 한도에서 자동 반복 호출로 우회하지 않는다.
- [ ] 수집과 분석 진행 상태를 사용자에게 보여 주되 부분 자료를 전체 성공으로 표시하지 않는다.
- [ ] 필요한 경우에만 독립 회사 수집의 제한된 병렬 처리를 검토한다. 제공자 한도·결과 순서·오류 격리 검사가 선행한다.

### P2. 큰 모델·문맥 확대가 필요한지 — 이번 표본으로 확정 불가

현재 16K 설정에서 단일 기업 평가·상세 원인의 입력/출력은 정상 종료했다. 상세 원인 생성은 입력 6113/출력255토큰, 심사는 입력4523/출력443토큰이었다. 이것만으로 긴 어닝콜 전체를 넣거나 56개 시나리오가 안정적으로 된다고 볼 수 없다.

- [ ] 긴 원문은 먼저 대상·기간별 검증된 근거를 선택한다. 프롬프트에 전체 파일을 계속 붙이지 않는다.
- [ ] 문맥 초과/잘림/계속된 잘못된 사실/메모리 오류를 실제 응답·서버 로그와 함께 분류한다.
- [ ] 코드·자료 선택을 바로잡은 뒤에도 재현되는 모델 한계라면, 동일 질문/동일 근거로 모델 후보를 비교한다. 모델 교체나 서버 재기동을 이번 작업에서 수행하지 않았다.

## 5. 15시 추가 상태 — 외부 실패와 문장 품질

한 프로브의 새 프로세스에서 고유번호 조회가 약12초 뒤 실패해 모델0회였다. 예외 종류가 원문에 남지 않아 시간 초과는 추정이며 확정 사실은 조회 실패다. 다른 실제 실행의 분기 수집·복합 답변은 성공했다. 이 현상을 모델 한계나 호출 한도 초과로 단정하지 않는다. [진단과 대응](외부재무_API_시간초과_진단_2026-10-28.md)에 관찰·추정·수정·다음 확인 순서를 분리했다.

분기 요청별 수집 총시간과 개별 재무 보고서 요청 시간은 새로 계측했다. 제공자 전체·기업 코드 캐시/목록·시세·생성/심사 전 구간의 일반 성능 계측은 아직 미완료다.

마지막 지침 검수는 실제 API 저장 자료의 해시/출처/기간을 보존하고 로컬 모델만 새로 호출했다. 첫 생성+심사는 통과했지만 반복·일부 어색한 문장이 남았다. 이 결과를 새 API/UI 성공이나 완벽한 문장 품질로 보고하지 않는다. 마지막 전체 검사는659개/50.676초다. 범위별 상태는 계획7-2 최신 기록을 따른다.


## 6. 문맥·뉴스 추가 검수 중 확인한 자료 경계(2026-10-28)

모델 자체가 목표 한국어 답변을 생성할 수 없다는 한계는 현재 표본으로 확정하지 않았다. 재무 후속·원가 설명·다른 기간의 혼재 평가·뉴스 묶음은 실제 새 로컬 생성에서 확인했다. 다만 프롬프트를 반복 보강한 것만으로 전체 상황의 일관성을 보장하지 않으며, 첫 생성/재작성/거절과 문장 품질은 분리해서 기록한다.

- 새 외부 수집은 총 17개 HTTP 요청(상한 24), 6.795초이며 관찰 상태는 모두 200이다. 삼성전자 2025년 1·2·4분기와 SK하이닉스 3분기 및 각각 전년 동기 재무 상태는 ok, 뉴스는 20건이다. 이는 이전 고유번호 조회 실패가 항상 지속된다는 뜻이 아님을 보여 주며, API 전체 안정성 보장은 아니다.
- 이 자료를 저장한 뒤의 대화 검수는 새 로컬 추론이다. 과거 실제 API 표본과 새로 수집한 기간 자료의 해시를 보존했다. 그 실행에서 외부 금융 재수집/Groq 호출은 0회다.
- 뉴스 검수 처음에는 저장 20건 중 앞 10건만 모델에 제공했다. 그 범위의 2개 사건을 현재 뉴스 전체가 2개뿐인 것처럼 해석하면 안 된다. 20건 전체 제공 검수에서는 브랜드·사내대출·규제 대응의 3개 사건과 같은 사건의 중복 기사 병합을 확인했다.
- 검색 발췌는 기사 전체가 아니다. 상세 후속이 발췌에 없는 사업 원인·회사 계획으로 길어져서는 안 된다. 더 깊은 사건 분석은 공식 원문 또는 합법적으로 확보한 기사 본문/회사 발표문을 출처·시점·숫자·정정 이력과 함께 연결하는 별도 수집 작업이 필요하다.
- 저장 재무의 최신 확정 연간은 2025년이다. 이 표본에는 올해의 최신 실적/구체적 회사 전망·시장 예상치가 없다. 그 자료로 올해/내년의 성장이나 목표 주가를 만들어 낼 수 없다. 전망 답변은 과거와 앞으로 확인할 판단 조건을 구별한다. 최신 공시·가이던스·컨센서스는 기존 수집 계약과 기간 검증을 확장하고 실제 API 검수를 해야 한다.
- 뉴스 단일 이슈 후속과 전망에서 문장 반복·일반론이 나타난 실행을 보존했다. 이를 “숫자 검사 통과=목표 품질 완료”로 보고하지 않는다. 최신 결과와 후속은 [문맥·뉴스 품질 검수](계획7-2_문맥뉴스품질_구현검수_2026-10-28.md)를 따른다.


최종 추가 확인은716개 자동 검사와18문항 핵심 대화다. 마지막 상대 PER 표현만 미세 조정 후2문항을 더 재검수했다. 이 수치들을 섞어20개의 독립 시나리오나 전체56개 완료로 세지 않는다. 모델이 생성한 형식 오류/출처 ID 누락은 확인된 근거에 한해 코드에서 정규화하고, 정규화한 답변도 수치·의미 심사를 거친다.

같은 로컬 모델의 의미 심사가 근거 없는 “이익 대비 낮은 주가”를 승인한 실제 사례도 있었다. 이 사례는 코드의 상대 PER 근거 검사를 추가해 보완했지만, 모든 금융 의미 오류를 완전히 검출한다는 증거는 아니다. 다음 검수는 정상 답변과 최소 변형 반례를 분리한 고정 자료 세트에서 첫 생성 성공·재작성·수치 오류·의미 오류·거절 오탐·문장 효용을 따로 집계해야 한다. 모델 후보 비교가 필요해지면 같은 자료/질문/예산으로 비교하고 기존 모델/서버/환경을 보존한다. 현재 관찰만으로 더 큰 모델이 반드시 필요하거나 현재 모델로 목표 답변이 불가능하다고 단정하지 않는다.
