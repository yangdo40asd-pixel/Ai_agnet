## 이번에 이어서 구현한 범위

작업 시작 당시 이미 대화형 캔버스 코드와 테스트가 수정된 상태였다. 그 변경을 보존하고 실제 코드와 계획의 차이를 보완했다. 시작 시 자동 검사는 167개가 통과했으며, 아래 결과는 이번 보완 후 검사다.

### 대화와 종목 탐색

- 일반 증권 질문은 대화 답변으로 처리한다. 짧은 단어나 ‘검색’이라는 설명 단어만으로 후보 탐색을 시작하지 않는다.
- `반도체 테마 찾아줘`처럼 명시적으로 요청하거나 ‘종목 찾기’ 버튼을 누른 뒤 테마를 답하면 탐색한다. 테마를 기다리는 중에도 PER 같은 개념 질문은 일반 대화로 처리한다.
- 후보 둘을 함께 지목하면 선택을 요청한다. 현재 종목과 다른 후보의 지표 질문에 현재 종목 근거를 붙이지 않는다.
- 후보 이름과 ‘바꿔줘’가 함께 있으면 종목을 변경한다. ‘지표’라는 말이 포함돼도 변경 요청을 먼저 처리한다.
- 분류기가 일반 질문을 임의로 탐색·재조회로 바꾸는 것을 막았다.
- 답변 본문·근거·유도 질문을 구분한다. 응답에는 `follow_up` 문자열이 필요하고, 질문 내용만 부적합하면 본문은 유지한 채 기본 질문으로 대체한다.
- 현재 종목의 특정 지표를 물으면 그 지표의 조회 근거를 함께 표시한다. 값이 ‘정보 없음’인 경우도 동일하다.

### 캔버스와 입력

- 분석이 끝났다고 캔버스를 자동 생성하지 않는다. ‘캔버스 추가’를 누르면 그 시점 결과와 엑셀을 독립 복사한다.
- 같은 결과는 한 장만 추가하며, 최신 순으로 최대 8장까지 보관한다. 카드를 닫아도 다른 카드와 현재 분석은 남는다.
- 카드마다 종목·기간·차트·다운로드 위젯을 구분한다. 과거 카드의 종목이나 기간을 고르면 그 카드의 후보와 조건으로 새 분석을 준비한다.
- 새 분석은 기존 카드의 지표·조회 시각·엑셀을 덮어쓰지 않는다. 사용자가 다시 캔버스를 추가해야 새 결과 카드가 생긴다.
- 후보 선택 버튼과 상세 표를 탐색 결과 대화 안에 넣었다. 편의 버튼과 글·첨부 입력은 대화 목록 아래에 배치했다.
- 제출한 파일은 그 사용자 메시지에만 남긴다. 다음 메시지 입력에는 자동으로 붙지 않는다. 새 대화는 작성 중 글·첨부·전송 대기 상태도 초기화한다.
- txt는 최대 8,000자를 참고 내용으로 전달한다. 이미지·PDF는 이름과 종류만 전달하며, 본문을 읽지 못한다는 안내를 표시한다.
- 진행 중 요청 잠금을 추가했다. 처리 실패 뒤 잠금을 해제하며 이미 만든 캔버스는 유지한다.

### 화면 배치

- 대화와 캔버스 열 비율은 2:3이다.
- 왼쪽 대화 목록과 오른쪽 카드 목록에 각각 스크롤 컨테이너를 두었다.
- 왼쪽은 자동 스크롤을 켰고, 오른쪽은 껐다. 새 카드가 추가될 때만 오른쪽 컨테이너 키를 변경해 상단에서 시작하도록 구성했다.
- 충분한 크기의 창에서는 뷰포트 높이를 기준으로 패널 높이를 계산한다. 작은 창에서는 바깥 스크롤을 허용해 입력이 잘리는 것을 피한다.
- Plotly의 휠 확대는 껐다. 실제 스크롤 위치·픽셀 배치는 브라우저 확인 전이므로 완료로 단정하지 않는다.
- 이번 환경의 Streamlit은 1.63.0이다. 사용한 컨테이너·업로더 기능을 고려해 기본 설치 목록에 `streamlit>=1.63.0`을 적었다.

## 실제 AI 검사

일반 PER 설명, 가상 종목의 PER 설명, PBR 누락 안내를 실제 Groq API로 확인했다. 종목 수치는 가상 검사 자료이며 실제 주식 조회값이 아니다.

1. 첫 실행: 일반 설명 성공. 종목 PER 답변은 숫자 검증에 걸렸고, PBR 사례는 사용 한도 오류가 발생했다.
2. 재생성 안내를 보완한 뒤 일반 설명과 종목 PER 사례가 통과했다. PBR 설명에서는 조회 근거가 빠지는 문제를 확인했다.
3. 현재 종목의 특정 지표를 물으면 해당 근거 ID를 포함하도록 검증한 뒤, PBR 누락 사례를 별도 재검수해 통과했다.

세 사례가 **각 수정 후 실행에서 통과**한 기록이며, 모든 사례가 한 번의 실행에서 함께 통과했다는 뜻은 아니다. 실제 금융·뉴스·DART 전체 연결 검사를 다시 수행한 것도 아니다.

- 초기 기록: `검수자료/계획4_대화_API_검수.json`
- 일반 설명·PER 재검수: `검수자료/계획4_대화_API_재검수.json`
- PBR 근거 재검수: `검수자료/계획4_PBR근거_재검수.json`

기록에는 호출 시각, 사례 종류, 가상 자료 사용 여부, 성공 여부, 근거 ID, 오류 코드만 남겼다. API 키와 모델 응답 원문은 기록하지 않았다.
