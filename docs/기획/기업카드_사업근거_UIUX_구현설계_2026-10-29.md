## 1. 맥락을 잊었을 때 먼저 읽을 사용자 의도

사용자는 테마를 물었는데 이름 세 개와 업종 한 줄, 상장 확인, 선택 요구만 받는 화면에 불만이 있었다. 이후 공식 KIND 제품 설명을 연결했지만 기업 설명은 여전히 짧고, ‘직접 연관성을 확인하기 어렵다’는 문장이 반복된다. 출처 버튼·출처 상세·기업 선택 버튼·후보 상세 표가 답변 사이에 쌓여 관리 화면처럼 보인다.

합의한 목표는 **관련 기업을 카드별로 소개하면서 무엇을 만들고 어디에 쓰이며 테마와 어떻게 연결되는지 이해시키는 대화**다. 사업 차이가 보이는 설명이 먼저이고 분석은 선택 사항이다. ‘관련주 더 보여줘’에는 새 기업만 추가한다. 기업 차이·용어·실적 후속 질문에는 질문에 맞는 답변을 하며 매번 기업 카드를 강요하지 않는다. 상장 검증과 사업 연관 검증은 서로 다르다.

카드가 길다는 이유만으로 품질이 좋은 것은 아니다. 제품 이름을 줄줄 복사하거나 동일 문장을 ‘사업/특징/전망’에 반복하면 실패다. 근거 없는 고객사·점유율·수혜·성장·실적 전망을 채워 넣어서도 안 된다. 자료에서 확인 가능한 역할과 차이를 쉽게 설명한다. 개발 진행 보고의 ‘브리핑입니다.’를 제품 챗봇에 넣지 않으며 제품 답변은 전문적인 ‘합니다/입니다’체를 쓴다.

## 3. 구현 가능성과 실제 자료 경로

가능하다. 다만 ‘카드를 그리는 일’, ‘설명할 자료를 확보하는 일’, ‘그 자료로 올바른 답을 생성하는 일’을 구분해야 한다. 로컬 모델이 기업을 알고 있을 것이라는 가정으로 빈 자료를 채우면 목표를 충족하지 못한다.

### 3.1 자료 확보 순서

1. 기존 KRX 상장명·종목코드로 회사를 확정하고 KIND 업종·주요제품을 최소 설명 근거로 유지한다.
2. 질문에 필요한 설명이 부족한 회사에 한해 공식 제품 페이지·사업 소개·IR 또는 사업보고서의 관련 절을 확보한다. 이미 충분한 회사까지 모든 원문을 다시 조회하지 않는다.
3. 회사 공식 홈페이지 주소는 검증된 기업 정보/공시의 주소에서 출발한다. 모델이 만든 주소나 검색 요약만을 공식 사업 근거로 채택하지 않는다. 프로젝트 Python에서 쓸 자료 경로를 구현해야 하며 개발 도구의 웹 검색을 앱 기능으로 착각하지 않는다.
4. OpenDART 경로는 기존 기업 고유번호 매핑→공시검색→적합한 정기보고서 선택→원문 다운로드→‘사업의 개요/주요 제품 및 서비스’ 관련 절 추출 순서다. 최근90일에 연간 보고서가 없을 수 있으므로 제한된 기간 확장 검색을 명시한다. 기존 뉴스/일반 공시 수집기의 기간·상위 개수 제한을 전역으로 풀지 않는다.
5. 공식 제품 설명과 최근 사건 자료를 구분한다. 오래된 기술 소개를 현재 실적 호조나 최근 투자 수혜의 증거로 쓰지 않는다. 발행일 미확인은 미확인으로 보존하며 조회일을 발행일처럼 표시하지 않는다.
6. 실패해도 확인된 KIND 근거와 성공한 다른 회사 자료는 유지한다. 설명 범위가 제한되면 그 부분만 제한하고 동일한 실패 고지를 카드마다 반복하지 않는다. 일반 업종만 확인된 기업을 상세 연관성이 검증된 기업처럼 소개하지 않는다.

OpenDART 원문은 인증키와 접수번호를 사용하는 ZIP 응답이다. 기존 키 설정을 재사용하며 신규 유료 검색 서비스를 기본 의존성으로 추가하지 않는다. 인증/이용 제한 상태는 실제 응답으로 구분하고 무제한·호출 무료 쿼터를 추정하지 않는다. [공식 원문 API 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003), [공시검색 API 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001).

### 3.2 실제 공식 자료에서 확인한 보강 가능성

- HPSP 공식 공고에는 반도체 전공정 및 고압 어닐링 사업 설명이 있다. 따라서 KIND의 ‘특수 목적용 기계’만으로 설명을 끝낼 이유는 없다. 해당 공고는2024년 자료이므로2026년 신규 발표로 소개하면 안 된다. [HPSP 공식 공고](https://thehpsp.com/ko/bbs/board.php?bo_table=notice&wr_id=24).
- 이수페타시스 공식 제품 페이지에는 AI 가속기용 PCB와 OAM 제품 항목이 있다. 반도체를 직접 만드는 회사와 기판을 공급하는 회사를 구별할 자료로 활용할 수 있다. 같은 페이지의 서로 다른 제품 절을 합쳐 한 제품의 기능처럼 만들지 않는다. [이수페타시스 공식 제품 설명](https://www.petasys.com/kor/product/ictester.jsp).
- 메모리 분야 축소 질문은 삼성전자·SK하이닉스의 공식 메모리 사업 설명을 확보해 분류해야 한다. KIND 짧은 제품명에 특정 단어가 없다는 것과 실제 해당 사업이 없다는 것은 다르다. [삼성전자 메모리 사업](https://semiconductor.samsung.com/kr/about-us/business-area/memory/), [SK하이닉스 사업 소개](https://www.skhynix.com/company/UI-FR-CP02/).

이 주소들은 가능성 확인 및 자료 수집 회귀 사례다. 특정 회사만 통과시키는 예외 코드나 고정 답변 사전으로 사용하지 않는다. 공식 페이지의 현재 접근/추출 가능성과 각 문장에 쓸 세부 근거는 구현 단계에서 다시 검증한다.

### 3.3 자료의 최소 계약

기존 `CompanyBusinessProfile`은 유지하고 상세 사업 근거를 별도 불변 자료로 구성한다. 최소 필드는 회사명/종목코드, 자료ID, 자료 종류, 문서·절 제목, 원문 URL, 관련 원문 발췌, 발행일/보고기간/조회시각, 원문 해시/추출기 버전이다. 제품·용도·공정 역할·사업 연관 주장마다 그 근거ID를 연결한다. 카드에 쓰는 사실과 쉬운 개념 풀이의 근거를 구별한다.

테마 연관은 **직접 사업 / 공급망·인프라 등 간접 연관 / 근거 부족**을 증거로 판단한다. 단어 한 번 일치했다고 직접 연관을 승인하거나 없다고 부정하지 않는다. 단계별 연결 근거가 없으면 간접 연관도 추정해 채우지 않는다. 회사 전체 사업과 해당 제품을 구별하고 최신 주요사업/매출 비중은 해당 자료가 있을 때만 설명한다.

새 외부 페이지 수집은 회사/공식 도메인 일치, 리다이렉트, 내부망 주소 거절, 시간·크기·문서 수 제한을 포함한다. 페이지 지시는 명령으로 실행하지 않고 자료로 처리한다. 기존 공시 XML 보안 제한도 보존한다.

## 4. 유지보수를 위한 최소 책임 분리

아래 새 이름은 제안 경계이며 착수 시 기존 동일 책임 모듈을 먼저 확인한다. 같은 일을 하는 계층을 중복 생성하지 않는다.

- `src/data/business_sources.py` 후보별 공식 사업 자료 검색·다운로드와 부분 실패를 담당한다. 기존 종목 매핑/HTTP 오류·크기 제한을 재사용한다. 답변 문장을 생성하지 않는다.
- `src/data/business_sections.py` 문서별 제목/절을 보존하며 필요한 본문을 추출한다. 문서 형식별 작은 추출기로 분리하고 회사별 정답 문구를 넣지 않는다.
- `src/agents/discovery_answer.py` 질문 범위·최근/누적 후보·필요한 사업 근거를 받아 카드 또는 일반 답변을 생성한다. 데이터 HTTP나 Streamlit을 직접 호출하지 않는다.
- `src/agents/company_cards.py` 기업 카드 스키마·기업/항목별 인용 연결·중복/누락 검증·결정적 대체 응답을 담당하는 작은 모듈로 검토한다. 금융 숫자·일반 근거 검증을 새로 복제하지 않고 기존 검증 진입점을 재사용한다.
- `src/ui/company_cards.py` 검증된 카드와 허용된 동작만 표시한다. 금융 계산·자료 조회·LLM 호출은 하지 않는다. 출처 UI는 기존 공통 출처 표시 함수로 통합한다.
- `src/ui/state.py`와 기존 수명주기 경로는 클릭 이벤트·문맥·결과ID를 관리한다. app.py는 배치와 연결만 담당하며 새 거대 분기문으로 모든 책임을 가져오지 않는다.

공통 계층→기존 공급자별 통신 구조는 유지한다. 회사 카드 때문에 Groq/Local에 별도 사업 로직을 복제하지 않는다. 변경 전에 호출자·저장 형태·테스트를 확인하고 필요한 작은 변경부터 적용한다.

## 5. 기업 카드 응답 계약과 검증

기본 선택안은 기존 뉴스용 `AnswerBlock`을 유지하고 `ChatResponse` 끝에 기본값이 있는 `company_cards=()`를 추가하는 것이다. 기존 필드 뒤에 필수 필드를 끼우지 않는다. 최종 자료형 결정은 CARD-I1에서 현재 호출자와 맞춰 확정한다.

기업 카드 최소 내용:

- 신뢰된 후보의 종목코드/회사명과 안정적인 카드ID.
- 한 줄 사업 요약, 필요한 사업 설명·제품의 용도·다른 기업과의 차이. 분량을 늘리기 위한 빈 제목/중복 문장 금지.
- 테마와의 연결 설명 및 근거 범위. 직접/간접 구분은 이해를 돕는 설명으로 표현하고 내부 상태코드를 그대로 보여주지 않는다.
- 설명 항목별 evidence_ids. 다른 회사 근거를 붙여 전체 출처 목록이 존재한다는 이유만으로 통과시키지 않는다.
- 행동은 코드에서 허용한 분석/사업 질문/근거 보기 종류와 신뢰된 대상 코드로 만든다. 모델이 임의 실행 명령·URL·위젯 키를 생성하지 않는다.

`output_contract.py`에 기업 카드용 형식을 추가하되 뉴스 이슈의 독립 사건·개수 규칙은 유지한다. `chat.py`의 기존 검사기를 완화해 아무 blocks나 승인하지 않는다. 기업 카드용 형식 검사 후 공통 숫자·말투·근거/의미 심사로 연결하고 카드의 요약/본문/연결 설명까지 검사한다. 회사 자체가 바뀐 카드, 존재하지 않는 근거, 근거 없는 고객사/비중/전망은 거절한다. 거절 시 해당 회사의 확인된 설명으로 제한하거나 유한한 재작성 후 대체 응답하며 성공으로 위장하지 않는다.

직렬화 `response_fields`, `ChatResponse.text`, 기존3값 순회 계약, 뉴스 blocks, 저장된 과거 메시지에 대한 호환을 확인한다. 새 필드가 없는 과거 답변은 기존 표시로 읽을 수 있어야 한다. 새 카드가 단문 변환/문자열 평탄화 단계에서 사라지지 않도록 모든 생성·복사·저장·복원 호출자를 점검한다. 글자/토큰 한도는 카드 수와 근거량에 맞게 별도 설정하고 기존 금융/뉴스의 한도를 전역 완화하지 않는다.

## 6. 실제 화면 구성과 사용 중인 라이브러리 제약

처음에는 채팅 한 영역만 보인다. AI 메시지는 짧은 공통 설명 다음 기업 카드를 세로로 배치한다. 기업명은 제목, 사업 역할은 짧은 보조 문장, 본문은 이해를 돕는 문단, 아래에는 실적 보기·출처 같은 해당 기업 동작을 둔다. 별도 ‘선택해 주세요’ 상자·코드 버튼 줄·후보 상세 표를 다시 붙이지 않는다. 카드 안에 여러 중첩 테두리를 만들지 않는다. 좁은 화면에서는 한 열을 유지한다.

자료에 따라1개 또는여러 개를 소개한다. 기존 한 요청당 후보1~3개 범위는 일단 유지할 수 있으나 전체 기업을 영구히3개로 제한하지 않는다. 더 보기에서 새 배치를 누적하고 중복은 제거한다. 사용자가 더 많이 요청하는 경우 한 배치 한도와 안내/추가 동작을 구분하고 숫자를 맞추기 위해 부실 기업을 채우지 않는다. 모든 카드에 긴 설명을 강제하지 않으며 충분한 차이·역할이 전달되는지를 평가한다.

설치된 Streamlit은 **1.63.0**이며 실제 시그니처에서 `st.container`와 `st.popover`를 확인했다. 기본 회사 카드는 네이티브 container와 버튼으로 만들고 출처는 가벼운 popover로 검토한다. 현재 `st.dialog`에는 `position` 인자가 없다. 온라인 최신 문서의 오른쪽 drawer 예시를 그대로 복사하거나 이 기능 때문에 의존성을 몰래 올리지 않는다. 출처 패널과 오른쪽 분석 캔버스는 별도 역할이다.

출처는 카드당 ‘출처 n개’ 같은 짧은 접근점 하나를 기본으로 하며 같은 문서의 링크를 여러 번 반복하지 않는다. 일반 문단 답변은 메시지 끝의 단일 접근점을 쓴다. 필요한 문장 인용표시는 유지하되 원문명·범위·기준일·조회 시각은 패널 안에서 확인한다. 패널 열기만으로 금융 조회·생성을 하지 않는다. **popover의 열림/닫힘은 기본적으로 rerun이 없지만 내부 내용은 미리 계산되므로, 그 내부에서도 네트워크/모델 함수를 호출하면 안 된다.** 이미 메시지에 저장한 근거만 표시한다. [공식 popover 동작 문서](https://docs.streamlit.io/develop/api-reference/layout/st.popover).

위젯 키는 메시지/답변ID+기업코드+동작으로 생성한다. 같은 기업이 과거/새 메시지에 나와도 충돌하지 않는다. 과거 카드의 출처를 현재 선택 기업 자료로 바꿔치기하지 않는다. 기업 클릭은 기존 분석 요청으로 한 번만 연결하며 금융 분석은 AnalysisResult/result_id를 보존한다. ‘출처 보기’가 종목 선택·분석을 실행해서는 안 된다.

캔버스는 사용자가 차트/재무표를 요청하거나 명확한 상세 보기 동작을 눌렀을 때 연다. 회사/기준기간을 표시하고 종목 변경 시 유지·갱신 여부가 명확해야 한다. 실행02는 기존 진입/대상/닫기와 대화 보존을 검수하고 자료 종류 확대·Excel 전체는08에 남긴다.

## 7. 사용자 대화별 수용 기준

1. **‘반도체 관련 종목을 찾아줘’**: 짧은 공통 안내 뒤 제조·메모리·장비 등 역할 차이가 있는 기업별 카드. 각 회사의 확인된 제품/용도/연관 설명과 출처, 선택적 분석 동작. 이름 나열이나 상장 확인을 답변의 결론으로 삼지 않는다.
2. **‘관련주 더 보여줘’**: 앞선 테마를 유지하고 새 기업만 소개. HPSP·리노공업·이수페타시스 같은 사례에서 장비/검사 부품/기판 역할을 근거로 구별. 제조사와 간접 인프라 기업을 동일 역할로 쓰지 않는다. 이 이름들은 고정 출력 정답이 아니다.
3. **‘이 회사들은 서로 뭐가 달라?’**: 기존 소개 집합을 대상으로 역할 차이를 설명하는 일반 대화. 현재 선택 한 회사로 축소하거나 같은 카드를 전부 반복하지 않는다. 실적 비교를 요청하지 않았다면 금융 전체를 재조회하지 않는다.
4. **‘그중 메모리 쪽만 알려줘’**: 공식 사업 근거를 바탕으로 해당 회사를 골라 설명. 단어 부재로 SK하이닉스를 빠뜨리는 반례 포함. 범위를 못 확인한 기업과 실제 비해당 기업을 구분한다.
5. **‘테스트 소켓이 뭔데?’**: 용어의 역할을 쉬운 말로 설명하고 해당 기업의 제품 설명과 연결. 과도한 카드·재무자료·선택 요구 없이 직접 답한다. 확인되지 않은 거래처/기술 우위는 추가하지 않는다.
6. **출처 클릭**: 해당 카드의 실제 원문과 뒷받침한 항목·날짜만 표시. 모델/API 호출0회, 선택 종목/분석 결과 불변, 닫은 뒤 스크롤/입력 유지.
7. **‘이 회사 주가 차트 보여줘’/실적 보기 클릭**: 바로 앞 기업 또는 명시 기업으로 정확히 연결. 차트 요청에서만 기존 캔버스 진입, 실적 질문에는 채팅 답변도 제공. 대화/출처/캔버스/Excel이 서로 다른 회사 result_id를 섞지 않는다.

최신 관심 테마를 시장 근거로 발견하는 E01 전체 기능은 실행04다. 이번에는 명시 테마의 기업 소개를 개선하며 시장 인기 순위를 이미 구현한 것처럼 답하지 않는다.

## 8. 호출 한도·대기·실패와 검증 방법

자료 수집/정규화 캐시는 기업코드·원문ID/정규URL·내용해시·추출기 버전·유효기간으로 관리한다. 생성 답변 캐시는 질문·후보 범위·근거 리비전·모델/정책까지 구분한다. 출처 열기나 과거 메시지 rerun은 캐시 재생성 계기가 아니다. 관련 절을 골라 문맥 예산을 관리하고 문서 전체를 로컬 모델에 밀어 넣지 않는다. 한 회사 보강 실패로 새 후보 배치 전체를 폐기하지 않는다.

검증은 저장된 원문과 모의 외부 응답→카드 계약/근거 반례→UI 상태 자동 검사→통과 후 최소 실제 공식 자료·로컬 생성→실제 화면 순서다. 실제 호출을 무작정 반복하지 말고 성공/재작성/대체 응답·모델/수집 시간·예외·캐시 적중을 분리해서 기록한다. 요청당 시간/문서/토큰 예산은 구현 전 기존 설정과 작은 측정으로 정하고 무한 재시도하지 않는다. 품질이 안 나왔을 때 자료 부족·추출 오류·분류·계약·검증·모델 한계를 구별한다.

필수 반례는 다른 회사 근거 혼입, 오래된 자료의 최신 사건 둔갑, 숫자/고객사 날조, 간접 관계의 직접 관계 둔갑, 중복 기업, 여러 제품 절 혼합, 근거 부족/일부 HTTP 실패, 저장된 구형 응답, 동일 기업 여러 메시지 키 충돌, 연속 클릭 중복 요청이다. 기존 뉴스 카드/숫자/CFS·OFS/기간 검증을 그대로 회귀 검사한다. 화면은1366/1920/390px에서 본문·카드·출처·입력·캔버스·키보드 접근과 겹침을 확인한다. HTTP/AppTest만 통과하면 육안 검수 완료로 쓰지 않는다.

## 9. 이번 조사에서 한 일과 하지 않은 일

현재 코드의 사업 자료·프롬프트·스키마·검증·UI·공시 수집 경로, 설치된 Streamlit 시그니처 및 공식 문서를 대조했다. 새 유료 서비스 없이 기존 자료 경로를 보강하고 네이티브 UI로 구현할 수 있는 방향임을 확인했다. 이 판단은 모든 기업의 원문 추출 성공이나 로컬 답변 목표 품질 달성을 뜻하지 않는다.

실제 카드 구현·자료 수집 확장·프롬프트 변경·앱/LLM 품질 테스트는 하지 않았다. 상위 계획의 새 구현/검증 체크는 전부 미완료로 둔다. 기존 체크와 증거를 보존하고 실행02 완료 뒤03-A로 복귀한다.

## 10. 02-A에서 확정한 화면·행동·응답 계약

2026-10-29 작업 재개 시 현재 호출자와 대조해 아래 계약을 확정했다. 이 절은 설계 완료이며 기업 카드가 이미 앱에 표시된다는 뜻이 아니다.

### 10.1 표시 상태와 전이

| 상태 | 기본 표시 | 허용 행동/전이 | 유지할 것 |
|---|---|---|---|
| 새 대화 | 환영 문장·입력·필요한 예시 | 자유 질문→의도 분류 | 빈 캔버스·후보 표·근거 패널 없음 |
| 최초 탐색 완료 | 짧은 공통 설명→이번 기업 카드 | 후속 질문/더 보기/기업 실적/카드 근거 | 기업 선택 전에도 설명 완결 |
| 추가 탐색 완료 | 새 기업 카드만 추가 | 기존 집합/최근 집합 후속 질문 | 이전 카드/선택/캔버스/결과ID |
| 비교·용어·범위 질문 | 질문에 맞는 문단/목록 | 새 질문 또는 필요한 상세 자료 | 같은 기업 카드 반복/선택 강요 없음 |
| 출처 열림 | 해당 메시지/카드의 원문·범위·기간 | 닫기/원문 링크 | 금융·모델 호출0회, 대상 변경 없음 |
| 실적 보기 | 클릭 회사의 기존 분석 요청→대화 답변 | 후속 질문/선택적 캔버스 | 한 번의 요청, 질문 원문/회사·결과ID 연결 |
| 차트 요청 | 해당 기업의 기존 캔버스 열기 | 닫기/기간 변경/후속 질문 | 채팅 내용, 정확한 기업/기간, Excel 계약 |
| 부분 실패 | 확인된 기업 설명은 유지, 실패 항목만 안내 | 해당 범위 재시도/다른 질문 | 전체 탐색/이전 결과 삭제 금지 |

데스크톱도 카드는 기본 한 열이다. 카드에는 기업명, 짧은 사업 역할, 필요한 사업/용도/테마 연결 문단, 실적·출처 행동을 둔다. 코드/시장 정보는 근거 또는 필요 목록에 둔다. 기업별로 빈 소제목을 채우지 않는다. 기본 메시지 읽기 폭760~880px는 시작값이며1366/1920/390px 화면 확인으로 조정한다. 근거 패널과 금융 캔버스 상태를 각각 관리한다.

### 10.2 응답 스키마 결정

기업 소개 생성은 `task=discovery_cards`로 분리한다. 기존 `task=discovery_answer`의 plain 후속 답변과 뉴스 `blocks`는 유지한다. 회사명·코드·버튼 라벨·실행 대상·위젯 키·카드ID는 신뢰된 후보와 코드가 결정하고 모델이 임의 생성하지 않는다.

모델 JSON의 최상위 필드는 `text`, `evidence_ids`, `follow_up`, `company_cards`다. 각 카드에는 `stock_code`와 `sections`만 허용한다. 각 section은 `role`, `text`, `evidence_ids`이며 role은 `summary/business/theme/difference`의 허용 목록이다. 같은 role 중복과 빈 text는 거절한다. 요약은 짧게, 필요한 상세는 다른 section으로 두고, 자료가 없는 역할을 억지로 채우지 않는다. 하나의 역할 안에서도 개별 문장을 의미 심사한다. 소개 대상은 요청의 후보 집합과 정확히 대조하며 현재 배치 밖 회사·중복 회사는 거절한다.

코드 자료형은 불변 `CompanyCardSection(role, text, evidence_ids)`, `CompanyCard(stock_code, stock_name, sections)`를 기본으로 한다. `ChatResponse`의 기존 여섯 필드 뒤에 기본값 `company_cards=()`를 추가한다. 뉴스 `AnswerBlock`을 기업 타입으로 전용하지 않는다. section마다 해당 회사가 소유한 근거만 인용할 수 있다. 도입의 회사 사실 주장도 별도 lead_evidence_ids로 검수한다. 사실 없는 짧은 연결 문장은 인용을 강제하지 않는다.

### 10.3 실제 변경 호출자와 호환 문턱

- `src/agents/output_contract.py`: 새로운 task 스키마만 추가. 기존 discovery_answer/chat_answer/news_relevance 형식 제한은 보존.
