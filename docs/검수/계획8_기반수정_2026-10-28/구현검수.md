# 계획8 첫 실행 — 종합 질문·검증 실패 기반 수정

날짜: 2026-10-28. 브랜치 woong. 계획8의 첫 실행 범위인 실패 원문 확보와 종합 질문 경로의 최소 연결을 수행했다. 계획8 전체 완료 보고가 아니다.

## 결과

- 기존 자동 검사 716개에 신규 21개를 추가해 **737개 통과 / 52.623초**를 확인했다.
- 실제 수집한 삼성SDI 자료를 보관한 뒤, 같은 자료로 변경 후 **새 로컬 생성과 의미 심사**를 수행했다. 변경 후 금융 API를 다시 수집한 종단 검수와 브라우저 육안 검수는 아니다.
- 최종 ‘삼성SDI는 어때?’는 약 22.114초, ‘왜 그런 거야?’는 약 17.148초에 반환됐다. 최종 실행 local HTTP 5회 모두 200이며, 종합 질문은 1차 중복 표현 거절→2차 생성→의미 심사, 후속 질문은 1차 생성→의미 심사였다. 최종 두 답변은 verified_fallback으로 대체되지 않았다.
- 종합 질문이 가격·PER만 반환하던 현상은 이번 표본에서 해소됐다. 그러나 비교 수치의 화살표 표현과 설명 중복이 남아 자연스러운 답변 완료로 체크하지 않는다.
- 후속 ‘왜?’는 오류 없이 반환됐지만 수치를 다시 설명하는 비중이 크고 원인을 충분히 설명하지 못했다. **정상 반환과 원인 분석 품질은 구분한다.** A02의 원인 분석과 V02의 전체 여정은 미완료다.

## 실제로 확인한 원인

1. 기본 리포트의 optional 설명 항목에 문자열을 반환하거나 news_ids를 생략했다. 이는 검증기의 오탐이 아니라 실제 생성 형식 위반이었다.
2. 초안은 실제 영업이익의 전기 금액을 10분의 1로, 재작성은 매출·영업손실의 당기 금액을 10분의 1로 잘못 옮겼다. 잘못된 금액은 계속 거절돼야 한다.
3. 적자 전환이 포함되면 기존 use_rate_sentences 조건이 false여서 비교 예시가 제공되지 않았다. 부호 있는 정확한 영업손익 전환 문장도 기존 검증 문법에 없었다.
4. 비교 자리표시자 뒤의 중복 표현으로 실패해도 재시도 지침은 무조건 rates 모드를 주장했다. 실제 요청 형식과 충돌하는 피드백이었다.
5. 출처에 존재하는 ‘배터리3사’·‘2차전지’가 숫자 검사에서 남았다. 기사에 같은 단어·숫자가 있는 경우만 산업 표현으로 대조하도록 했다.
6. 종합 질문 의도가 수집·근거·대체 답변에서 일관되게 사용되지 않았다. 가격만 보유한 결과에 추가 재무자료를 요청하지 않는 조건도 재현했다.

## 변경 파일과 책임

- `src/agents/question_goal.py`: 부작용 없는 공통 질문 목적. 종합 기업 질문과 지표·뉴스·원인·전망을 구분한다. 모든 의도·기간·비교 상태 계약을 완성한 것은 아니다.
- `src/agents/request.py`: 기존 대상 검증을 유지하면서 목적을 ChatIntent에 추가하고 종합 요청의 all 범위를 보존한다.
- `src/analysis_flow.py`: 종합 질문에서 미수집 금융·재무·뉴스 보완 필요를 판단한다. 자격 설정이 없는 DART를 반복 요청하지 않는다.
- `src/agents/answer_quality.py`: 종합 질문의 핵심 비교·뉴스를 선택하고, 후속 원인 질문에서 직전 답변이 실제 사용한 재무 근거를 이어받는다.
- `src/agents/chat.py`: 비교 수치 인용 계약과 오류별 재작성 피드백을 수정하고, 실패 시 확보된 재무 비교를 남긴다.
- `src/agents/company_overview.py`: 검증된 동일 회사·기간·회계기준의 비교만으로 제한 답변을 구성한다. 분석 성공으로 표시하지 않는다.
- `src/agents/report.py`: optional 설명의 객체·근거 형식을 명시하고 형식 실패를 명시적 검수 문맥에서 기록한다. 검증기는 완화하지 않았다.
- `src/agents/financial_numbers.py`: 정확한 항목·부호·전기/당기 값·전환 방향을 대조한 경우에만 적자/흑자 전환 수치를 수용한다. 같은 문장의 기간 검사는 기존 검증을 그대로 거친다.
- `src/agents/literal_numbers.py`: 인용 뉴스에 동일 표현이 있는 산업 이름·기업 수만 검사 사본에서 대조한다. 원문과 표시 문장은 바꾸지 않는다.
- `src/diagnostics.py`: 기본 로그 정책을 유지하며 명시적 capture_validation_events 검수에서만 생성 결과·근거·오류를 수집한다. sink 오류가 답변 경로를 바꾸지 않고 키/비밀 필드는 수집에서 제외한다.
- `tests/test_plan8_company_overview.py`, `tests/fixtures/plan8_rejected_amounts.json`: 실제 잘못된 금액과 정상·반례를 회귀 보호한다.

## 검증 범위

신규 21개는 목적 구분, 종목 대상 유지, 미수집 자료 보완, 인증 없는 반복 수집 방지, 종합 근거 선택, 적자/흑자·손실 변화의 제한 응답, 복수 회사·기간·회계기준 혼합 거절, 비정상 숫자 거절, 진단 격리/민감 필드 제외, 후속 근거 초점, 원문 숫자 대조, 정확한 음수 전환과 틀린 금액·부호·항목·기간 거절, 오류별 피드백을 확인한다.

이전 실패 자료를 삭제하거나 수치 검사를 무조건 승인하도록 바꾸지 않았다. 실제 틀린 금액 두 응답은 회귀 픽스처로 보존해 계속 거절하는지 확인했다.

실제 기본 리포트는 형식 지침 수정 후 중간 검수에서 반환됐으며 해당 단계의 결과는 plan8_after.json에 기록했다. 최종 버전에서의 새 기본 리포트 생성은 따로 반복하지 않았으므로 최종 두 문항 결과와 합산하지 않는다.

## 남은 작업과 다음 시작점

1. ‘왜?’가 실적 결과를 재진술하는 데 그치지 않도록 필요한 원가·비용·사업 근거의 수집 가능 범위를 확인한다. 이번 삼성SDI 결과에는 비용 비중 근거가 없었다. 이미 조회 가능한 자료까지 놓쳤는지, 별도 원문/전체 계정 수집이 필요한지 확인한다.
2. 수치 자리표시자의 화살표 나열과 중복 표현을 의미 보존 방식으로 개선한다. 잘못된 수치까지 정상화하지 않는다.
3. 기본 리포트 생성 뒤 원래 질문을 다시 생성하는 경로를 정리해 약 65초 지연을 줄인다. 이번 변경 후 측정은 보관 자료 기반 대화 시간이므로 이전 새 API 수집 포함 81.5초와 직접 속도 비교하지 않는다.
4. ‘관련주 더 보여줘’, ‘그 기업들 비교’의 탐색·집합 참조를 구현한다. 세 종목 계약·사업 연관 근거 수집도 여전히 미완료다.
5. UI·선택적 캔버스·주제 전환·요약/저장/종료 및 A~F 전체 흐름을 순서대로 검수한다.

상태 ID·AnalysisResult·Local/Groq·기존 계산/출처·캔버스/Excel을 보존했다. 서버·모델·환경설정·WBS를 변경하지 않았고 Git 커밋·푸시하지 않았다. 기존 다른 AI의 미커밋 변경을 폐기하지 않았다.

## 실행 증거

- `plan8_failure_raw.json`: 변경 전 실제 원문·근거·검증 오류.
- `plan8_after.json`, `plan8_final.json`: 중간 실패·수정 과정. 최종 성공률에 섞지 않는다.
- `plan8_release.json`: 최종 두 문항·생성/심사·시간·재시도 기록.
- `plan8_release_full.log`: 전체 737개 검사 결과.
- `plan8_targeted3.log`: 신규 21개 검사 결과.
- `code_hashes.json`: 검수 코드·픽스처 해시. 마지막 diagnostics 모듈 설명 변경은 동작과 무관한 문서 수정이다.
