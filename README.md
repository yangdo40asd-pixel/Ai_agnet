## 실행하기

기존 환경에서는 프로젝트 루트의 start.bat을 사용한다. 직접 실행하려면 다음과 같다.

```powershell
Set-Location D:\ai_agent
.\venv\Scripts\python.exe -m streamlit run .\src\ui\app.py
```

새 환경의 기본 실행 패키지는 requirements-core.txt 기준이다. 챗봇용 추가 패키지는 없으며 기존 Groq 설정을 사용한다.

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-core.txt
```

기존 .env를 .env.example로 덮어쓰지 않는다. 현재 설정은 src/config.py가 읽으며 실제 키는 코드·화면·문서·로그에 기록하지 않는다.

| 설정 | 용도 |
|---|---|
| GROQ_API_KEY | Groq의 AI 호출 인증 |
| GROQ_MODEL | 기본 openai/gpt-oss-20b. 모델 이용 권한/한도는 계정과 제공 시점에 따름 |
| NAVER_CLIENT_ID / NAVER_CLIENT_SECRET | 현재 NAVER API HUB 뉴스 인증. Developers 검색 API 인증과 혼동하지 않음 |
| DART_API_KEY | OpenDART 기업 재무 조회. 미설정 때 재무 영역은 수집하지 않음 |
| NEWS_SORT | date(기본) 또는 sim |
| REQUEST_TIMEOUT | 뉴스·AI·DART의 명시적 요청 제한 설정. KRX/yfinance 모든 내부 요청에 적용되는 전역 제한은 아님 |

## 현재 처리 순서

1. 왼쪽 입력은 글, png/jpg/webp 이미지, txt/pdf 파일을 받는다. 빈 값과 1,200자, 첨부 종류와 5MB 제한을 검사한다. 이미지와 PDF 본문은 모델에 넘기지 않는다.
2. 테마 후보 탐색, 공식 이름·코드로 지정한 종목 조회, 개념 설명, 현재 종목 후속 질문을 구분한다. 자유 대화는 LLM 분류와 코드의 대상·범위 검사를 거친다. 전용 검색 폼은 명시적 검색 행동을 전달한다. 후보 탐색용 테마는 120자 이내다.
3. 답변은 입니다·합니다체로 제공하고, 불필요한 후속 질문은 생략한다. AI의 확인 질문을 사용자 입력 버튼으로 복제하지 않는다. 예상 질문은 현재 자료로 지원하는 범위만 제안한다.
4. Groq에 후보3개를 요청하고 응답 형식을 검사한다. KRX 목록으로 이름·코드·시장을 대조하고, 필요하면 1회 재제안한다.
5. 선택 전에는 상세 금융·재무·뉴스를 호출하지 않는다. 선택 뒤에 주가/PER/EPS/BPS/PBR, 일별 OHLCV, DART 최근 3개 연간 재무, 뉴스 제목 최대 3건, AI 설명을 수집한다.
6. 수집 결과와 핵심 분석 리포트를 채팅에 표시한다. ‘차트·근거 보기’를 누르면 해당 답변의 결과 ID로 카드가 열린다. 클릭 전에는 오른쪽 영역 자체를 표시하지 않는다. 카드에는 지표·차트·재무·뉴스 근거와 엑셀 준비 버튼이 있다.
7. 후속 질문은 해당 결과와 최근 대화로 답한다. 뉴스·시세는 15분, 금융 지표는 5분의 재조회 기준을 적용하며, 요청 범위가 미수집이거나 시세 기간을 바꾸면 필요한 영역을 조회한다. 이 시간은 갱신 판단 기준이며 원천 데이터의 실시간성을 보장하지 않는다. 새 테마는 기존 대화·캔버스를 보존한다.
8. 이전 캔버스의 종목·조회 기간을 선택하면 새 결과를 만든다. 기존 카드는 스냅샷으로 보존한다. 일·월·연 표시 간격 변경은 동일 원자료의 OHLCV 집계다. 같은 결과를 다시 열면 해당 카드가 맨 앞으로 이동하고, 새 조회에는 별도의 결과 ID를 부여한다. 카드는 최대 8장, 답변 참조 결과는 최대 20개 보관한다.

뉴스/AI/DART 등의 일부 실패는 영역별로 보관한다. 기본 종목 식별·필수 금융 실패는 중단하고, AI 설명·엑셀 생성 실패 때 수집 결과와 카드를 보존한다. complete는 해당 결과의 금융·뉴스·AI 및 수집 영역 상태를 함께 확인하며, 프로젝트 전체 완료나 WBS 100%를 뜻하지 않는다. 뉴스만 요청한 경우 종합 리포트는 ‘요청하지 않음’으로 구분한다.

PER는 제공 trailingPE를 우선하고, 없으면 조건에 맞는 원화 TTM 희석EPS로 계산해 근거/종료일을 표시한다. 공식 ROE 제공값과 자체 계산을 구분한다. 자체 ROE에는 평균자본 우선과 기초값 없을 때 기말자본 대체 경로가 있으므로 모든 ROE를 같은 산식이라 설명하지 않는다.

## 화면과 파일

- 첫 진입: 간단한 소개와 예시 질문 3개, 메시지 입력을 제공한다. 예시 선택은 입력창만 채우고 전송해야 조회한다. 대화가 시작되면 초기 소개·예시를 접고 현재 자료에 맞는 후속 질문을 최대 2개 표시한다.
- 좌측: 증권 대화와 후보 버튼·상세 표. 메시지 입력·전송을 먼저 배치하고 첨부·추가 작업은 펼침 영역에 둔다. 일반 개념 답변에는 종목 상세 버튼을 붙이지 않는다.
- 우측: 명시적 열기 전에는 숨김. 연 뒤에는 종목별 카드에 주가/PER/PBR/ROE, EPS/BPS, 가격/거래량, 재무, 뉴스, 엑셀 준비·다운로드.
- 대화는 현재 세션에서 최근 40개 메시지를 유지하고 AI에는 최근 12개 문맥을 전달한다. 서버 재시작·새 세션을 넘는 영구 저장은 지원하지 않는다.
- 관련 후보: 최대 3개이며 선택 종목의 시세를 재사용하고, 미선택 후보는 각각 최근 1개월을 조회한다. 추가 호출은 최대 2회이며 후보별 실제 계열 또는 실패 상태를 표시한다.
- 엑셀: 요약·핵심지표·일별시세·손익계산서·재무상태표·현금흐름표·관련뉴스·출처및산식의8시트. 네이티브 차트는 실제 데이터 셀 범위를 참조한다.
- 종목/가격 범위/명시 재조회 변경 시 결과와 파일을 무효화하고 같은 결과의 rerun/다운로드는 세션 자료를 재사용한다. 이는 제공자별 네트워크 캐시 구현과 다른 기능이다.
- 캔버스에 이미 보관한 결과·엑셀은 새 분석과 별도 스냅샷이다. 첨부는 보낸 메시지에만 보관하며 다음 메시지로 자동 이월하지 않는다.
- 과거 답변의 상세 버튼은 당시 종목·결과를 연다. 결과가 보관 범위를 벗어났으면 안내와 해당 종목의 재조회 질문 작성 버튼을 제공하며 사용자가 전송해야 새 결과를 만든다. 캔버스를 닫아도 대화는 유지된다.
- 뉴스·이슈 대화는 핵심 답과 설명별 제목·본문·근거로 구성할 수 있다. 출처는 해당 설명 아래에 표시하고 같은 URL은 중복 링크하지 않는다. 값·개념·짧은 요청에는 이슈 카드를 강제하지 않는다.
- 질문/답변 시각과 자료 조회 시각·거래 기준·뉴스 발행·재무 기간을 구분한다. 확인되지 않은 시점은 미확인으로 표시한다. 뉴스는 제목 기반이며 기사 본문을 수집하지 않는다.

## 패키지

활성 core 목록은 streamlit, yfinance, finance-datareader, requests, pandas, plotly, XlsxWriter, python-dotenv, langchain-groq다. 상세 버전은 구현 결과 정리 문서에 **현재 설치값**으로 기록한다. 고정 버전/재현 환경을 보장하는 lock 파일은 아니다.

openpyxl은 src/export/excel.py의 대조 함수와 자동/실제 검수에서 사용한다. 현재 requirements-core.txt에는 포함되지 않으므로 새 환경에서 그 검수를 수행할 때 별도로 필요하다.

```powershell
.\venv\Scripts\python.exe -m pip install openpyxl
```

과거 requirements.txt는 실험/후보 목록이다. 설치돼 있거나 목록에 있다는 이유만으로 사용 API/구현 완료로 세지 않는다. Selenium·crewai·reportlab 등은 현재 핵심 실행 기능의 근거가 아니다.

## 자동 검사와 실제 API 기록

2026-10-25 외부 네트워크를 차단한 자동 검사 **281개**를 통과했다. 실제 검수 도구에는 생성·검증·재요청의 HTTP 호출마다 기본 65초 간격과 실행당 6회 호출 예산을 적용하고, 한도·사용량을 기록한다. 검수 중 429 응답에는 자동 재시도하지 않는다. 최신 변경·실제 답변 평가·남은 작업은 [계획5의 17.14절](계획5_근거기반_대화형분석_개선기획.md)을 따른다. 일반 앱 전체의 요청 제한을 바꾼 것은 아니며, 공유 계정 사용량·일일 토큰 한도까지 보장하지 않는다. 개별 평가 기준의 오판과 다양한 표현의 안정성, 실제 화면 육안 확인과 기본 리포트의 의미 검증 확대는 남아 있다.

```powershell
Set-Location D:\ai_agent
.\venv\Scripts\python.exe scripts/verify_local.py
```

제품 코드에는 모의 객체를 판별해 실제 단계를 생략하는 분기가 없다. verify_local.py는 외부 네트워크를 차단하며, 각 검사는 제공자 경계의 응답만 대체한다.

전체 금융·뉴스 연동의 기존 기록은 검수자료/실제_API_검수.json에 있다. 챗봇 추가에서는 실제 AI API로 일반 용어 질문·선택 종목 PER 설명·PBR 누락 안내를 확인했다. 챗봇 검사에는 가상 종목 자료를 사용했으며 금융·뉴스 API 전체를 재검수한 것은 아니다. 기록: [챗봇 API 검수](<D:/ai_agent/검수자료/챗봇_API_검수.json>).

계획4에서도 같은 종류의 세 사례를 새 답변·유도 질문 형식으로 각각 확인했다. 초기 숫자 검증 실패·사용 한도·PBR 근거 누락과 수정 후 결과를 별도 보존했다. 실행 도구는 `scripts/verify_canvas_chat.py --live`이며, 이 검사는 실제 금융·뉴스 API를 호출하지 않는다.

실제 검수를 다시 실행하려면 다음 명령을 명시적으로 사용한다. 외부 API 사용량이 발생하고 기본 테마 간격은 현재 스크립트 기준35초이며 JSON 파일은 갱신된다.

```powershell
.\venv\Scripts\python.exe scripts/verify_live.py --live
```
