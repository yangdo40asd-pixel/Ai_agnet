## 2. 실제 변경과 책임

### T00: 원자료 확보

`src/data/news.py`는 첫 검색 display=10, 필요한 경우 회사명 검색/다음 페이지 1회, 총 20건 상한으로 변경했다. 기존 parse_news 기본 3건 계약은 유지한다. 검색 발췌 description은 정제 후 별도로 보관한다. 추가 요청의 인증/429/시간 오류가 발생해도 먼저 확보한 자료는 partial로 유지한다. URL이 같은 중복은 합치며 최종 ID는 수집 결과 내에서 안정적으로 부여한다.

추가 검색 판단은 ‘제목에 회사가 명시된 후보 수’다. 독립 사건 수나 테마 연관성 판정이 아니다. 동일 사건을 다룬 서로 다른 URL의 기사 3건을 수집했다고 독립 이슈 3개로 간주하지 않는다. 같은 사건 병합은 U의 책임이다.

`src/data/disclosures.py`는 ‘공시/공식/계약’이 명시되고 DART 키가 설정된 요청에만 기존 기업코드 매핑을 재사용한다. 최근 90일 목록 1회, 선택한 원문 최대 2회를 조회한다. 기업코드 캐시가 없다면 기존 매핑 조회가 추가될 수 있다. 실제 다운로드한 XML을 읽었을 때만 official_disclosure를 부여한다. ZIP은 메모리에서 읽으며 파일로 풀지 않는다. 압축 응답 2MB/해제 XML 합계 4MB의 파싱 제한과 DTD/ENTITY 거절을 적용했다. 이 제한은 스트리밍 다운로드 전체의 메모리 상한을 보장한다는 뜻이 아니다.

원문은 AnalysisResult.source_documents에 보존한다. 단일 공시의 확보는 정정 관계나 최신 유효 값 확인을 뜻하지 않는다. 공시 목록의 제목만 확보한 자료를 공식 원문 Fact로 등록하지 않는다. 계열사·소유 관계의 자동 수집/공식 정정 그래프는 구현하지 않았다.

`pipeline.py`, `agents/request.py`, `ui/app.py`는 질문 원문을 공시 수집까지 전달하고 공시 요청을 뉴스 자료 범위에 포함한다. UI의 로컬 요청은 수집부터 답변 심사까지 같은 turn_budget을 공유한다. 뉴스·공시의 신규 요청은 남은 시간을 확인한다. 기존 모든 금융 제공자의 내부 호출에 강제 취소 기능을 새로 구현한 것은 아니다.

`news_relevance.py`는 최대 20건을 5건씩 심사한다. 후보/ID 원본을 보존하고 새 무제한 재시도를 만들지 않는다. 질문별 모델 입력은 뉴스 근거 최대 4건을 우선 선택하고 명시 필수 ID를 보존한다. 모델용 Fact는 verified만 최대 8개/근거로 제한한다. 원본의 보류 사실·원문은 삭제하지 않는다. 실제 4K 로컬 모델에서 새 입력 크기와 속도가 적절한지는 W-B에서 확인해야 한다.

### T01/T04: 사실 구조와 등록

`src/models.py`의 frozen StructuredFact에 Fact ID, 근거 ID, Decimal 값, 단위, 항목, 기업, 방향, 원문 문자열·span·SHA256, 자료 범위, 기사 발행/사건일/재무기간, 검증 상태, 잠정/계획·이력·합산 속성과 계산 입력/산식을 둔다. 기존 자료형의 필수 인수 순서와 AnalysisResult/result_id 계약을 보존했다.

`src/data/text_facts.py`는 LLM을 호출하지 않는 결정적 추출·등록 모듈이다. 주가/변화율, 지분율, 투자/계약 금액, 매출/영업이익 등 **명시적으로 인식한 항목만** 다룬다. 회사나 항목이 불명확하거나 다른 회사, 모호한 지분 역할이면 deferred로 남긴다. 외부 후보는 register_fact가 고정 원문에서 다시 추출한 값/위치/속성과 비교해 변조를 거절한다. 모델의 자기확인 결과를 verified로 옮기지 않는다.

추출은 원문 앞 6,000자로 제한한다. span은 원문 위치이고 source_hash는 전체 원문 해시다. 원문 뒤쪽이 바뀌어도 기존 후보의 해시가 달라진다. 원문 나머지 부분을 읽어 사실 등록까지 마쳤다고 표시하지 않는다. 일반적인 DART 표 전체를 의미적으로 해석하거나 임의의 다중 기업 지분 관계를 해결하는 파서는 아니다.

‘잠정’은 잠정으로 유지하며 확정치처럼 쓰지 않는다. 합산 지분은 단독 보유로 바꿀 수 없다. 음수 하락률은 크기와 방향을 구분하고, 음수 상승률처럼 부호와 방향이 충돌하는 원문은 보류한다. ‘최초 공시 600/정정 공시 300’의 **주입된 명시적 관계**에서는 과거/현재 역할을 보존한다. 공식 정정 관계 자동 식별(Y)은 별개다.

contract_scale_fact는 검증된 같은 기업·같은 원화 입력의 계약금액/연간 매출만 Decimal로 계산하며 입력 Fact ID·Python 산식을 기록한다. 가상 300억원/1,200억원=25%를 검사했다. 분기 분모·0분모·타 기업·보류 입력은 거절한다. 이 계산 헬퍼는 자동 정정 수집이나 새로운 사용자 대화 기능에 연결한 것이 아니며, 결과 항목도 매출 손실률이 아니라 contract_scale_ratio다. 공시 전체 기간/연간 매출의 비교라는 설명은 후속 답변 구현에서 유지해야 한다.

### T02/T03: 답변 결합과 기존 검사 보존

`src/agents/news_numbers.py`는 **실제로 인용한 근거의 verified Fact만** 대조한다. 숫자 크기만 같다고 허용하지 않는다. 항목·기업·기간·단위·방향·잠정/합산/이력·확인 범위를 함께 확인한다. 공시 한 건에서 수집한 document_only 사실은 ‘조회한 공시에 기재된 값’으로만 사용할 수 있으며 ‘현재/최신 유효 값’으로 승격하지 않는다.

승인 숫자는 기존 검사에 넘기는 사본에서만 마스킹하며 표시 문장은 보존한다. chat.py는 이후 기존 financial_numbers/CMP/미등록 숫자 검사를 그대로 수행한다. report.py의 기본 리포트도 같은 수치 검사를 사용한다. 생성·재작성·공통 근거 심사 지시는 새 계약과 모순되지 않도록 조정했다. 정상 뉴스 수치를 허용한다는 이유로 기존 인과·관련성·금융 의미 심사를 우회하지 않는다.

`evidence.py`는 뉴스 제목/검색 발췌/확보한 공식 원문을 구분한다. 공시 원문의 verified/deferred 후보를 보존하고 모델용 projection에서 verified만 전달한다. `answer_quality.py`는 자료 범위별 설명과 한정된 모델 입력을 담당한다. `ui/answer.py`는 기존 ‘기사 발행’을 보존하고 공식 공시에만 ‘공시 접수’를 사용한다. 본문에 Fact 해시나 API 세부 메타데이터를 새로 나열하지 않는다.

## 3. 정상·반례와 증거

새 검사 45개를 기존 392개에 추가했다. 하위 subTest의 여러 변조 조합은 별도 unittest 개수에 합산하지 않았다.

- `test_text_facts.py` 16개: Decimal 금액 정규화, 잘못된 쉼표/규모 단위 거절, 회사/항목/날짜/기간, 변조 후보, 잠정/합산/이력, 전체 원문 해시, 계산 입력 추적.
- `test_news_numbers.py` 13개: 정상 가격/변화율/날짜, %/%p, 잘못된 회사/방향/항목/기간, 뉴스→공시 승격, 이력/현재, 미인용 다른 기사 숫자 차용.
- `test_t_integration.py` 7개: 실제 파이프라인의 질문/스냅샷, 기본 리포트 수치 검사, 모델용 사실 필터, 20건 심사/입력 상한, 공시 대상 격리, 누적 시간 예산, 공시 보류 사실 보존.

대표 정상 입력: ‘가상회사 주가 22만2500원으로 4.46% 상승’ → ‘주가는 222,500원으로 4.46% 상승했습니다.’를 허용한다. ‘외국인 지분율 4.46%’, ‘4.46% 하락’, ‘4.46%p 상승’, ‘99% 상승’, 타사 주가로 전용하는 반례는 거절한다. 뉴스 제목의 기사 발행 시각으로 사건일을 만들어도 허용하지 않는다.

기존 단위별 근거 심사에서 한 문장이라도 unsupported이면 전체 승인을 뒤집는 검사, 사업 계획을 가동 완료/인과로 바꾸는 반례, 재무 비교·연도·단위·자리표시자·스냅샷·XLSX 검사를 그대로 포함했다. 의미 심사 응답은 통제된 가상 판정이다. 실제 LLM이 잘못된 인과를 언제나 거절한다고 증명한 것은 아니다.

## 4. 공식 문서 대조와 남은 작업

[NAVER API HUB 뉴스 검색 문서](https://api.ncloud-docs.com/docs/naver-api-hub-search-news)의 display/start/description/pubDate 계약과 [DART 공시 목록](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001), [공시 원본파일](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003) 경로를 대조했다. 문서의 접근 경로 확인과 실제 키의 권한/응답 성공을 구분한다. 새 유료 계약이나 기사 본문 전체 크롤링은 추가하지 않았다.
