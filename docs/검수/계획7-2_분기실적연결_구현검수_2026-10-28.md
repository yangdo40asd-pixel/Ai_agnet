# 계획7-2 분기 실적 연결 및 자동 보완 검수 — 2026-10-28

이전 기준선: 두 기업 연간 비교·실적 평가 보강 후 620개 검사 통과. 이번 최종: **659개 통과(50.676초), 신규 39개**. 작업 경로 `D:\ai_agent`, 브랜치 `woong`. 사용자 요청에 따라 해결 가능한 문제는 확인→수정→재검증을 이어갔다. 코드·자료 수집 성공·LLM 답변 성공·문장 품질 완료를 구분한다.

## 1. 이번 작업의 목적과 범위

분기 계산기가 있다는 이유로 분기 질문이 되는 것으로 판단하면 안 된다. 기존 수집은 연간 사업보고서만 요청했고, 분기 자료를 챗봇 근거에 연결하지 않았다. 이제 **명시한 연도·분기의 3개월 실적과 전년 동기**에 한정해 필요한 보고서를 수집하고, 검증된 수치로 답변한다. 기존 연간 결과·두 기업 연간 비교·단일 종목 result_id·과거 캔버스·Excel 계약은 보존한다.

사용자 목표는 ‘수치 나열’이 아니라 질문의 결론과 확인한 숫자·의미를 연결하는 금융 대화다. 전문적인 입니다·합니다체, 필요한 부분만 설명, 자료에 없는 원인·미래 수치·누락 사유 생성 금지, 질문한 분량 존중을 유지한다. 목표 MD 1~56 전체를 완료했다고 표시하지 않는다.

## 2. 처리 순서와 책임

1. **명시 기간 판정:** `data/report_period.py::QuarterRequest`가 연도·분기·연결/별도·3개월/전년 동기 범위를 고정한다. 분기만 말하면 사업연도를 확인하고, 비연속 연도·여러 분기·누적/전분기 요청은 지원 범위를 알린다. 명시 연도를 다른 연도로 대체하지 않는다.
2. **한정 수집:** `data/quarterly.py::collect_quarterly_financials`가 종목→공식 기업 코드→해당 분기와 전년 동기 보고서를 조회한다. 1~3분기는 두 보고서, 4분기는 연간·3분기 누적의 두 연도 자료가 필요하다. 2015년 이전 자료를 요청하지 않는다. 인증·호출 한도는 자동 반복하지 않는다. 명시한 CFS를 OFS로 바꾸지 않으며, 자동 기준에서만 CFS가 모두 empty인 경우 OFS 전체 계열을 조회한다.
3. **정규화와 계산:** 기존 `financials.normalize_statement/build_quarter_comparison`을 재사용한다. IS/CIS의 `thstrm_amount`는 분/반기에서 3개월 금액이며 `thstrm_add_amount`는 누적이다. 4분기는 같은 연도·회계기준의 연간에서 3분기 누적을 차감한다. 중복 기간을 임의 선택하지 않고, 당분기 행의 통화·기간형을 확인한다. [OpenDART 공식 명세](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)
4. **근거 구성:** `quarterly_evidence`가 QFIN(해당 분기 값), Q_CMP(동일 분기의 전년 동기 비교)를 만든다. 원화, 분기, 연도, 회계 기준, 공시 접수번호·링크, 원자료 조회시각, 4분기 차감 근거를 보존한다. 금액 증감 계산은 기존 Decimal 계산 함수 `amount_change`를 공유한다. 적자/0 분모를 성장률로 만들지 않는다.
5. **대화와 상태:** `analysis_flow.needs_data`, `pipeline`, `ui/app.py`가 같은 기간은 재사용하고 다른 기간이나 만료 시 필요한 자료를 조회한다. 원 질문을 바꾸지 않고 보류 질문과 문맥 기간을 별도로 전달한다. 새 결과는 새 result_id이며 이전 캔버스는 원래 결과를 유지한다. 새 회사·연도·연간 질문에 이전 분기를 임의 승계하지 않는다.
6. **생성과 검증:** `agents/quarterly.py`가 요청 분기 근거를 선택하고 기존 chat 생성·숫자·의미 심사를 모두 거친다. 숫자 검사의 사본에서만 확인한 분기 표기와 제한된 문형을 정규화한 뒤 기존 산술 검사를 재사용한다. 모델·화면·저장 원본의 kind는 quarterly이며 연간 근거로 바꾸지 않는다. 연도·금액·증감 방향 불일치는 계속 거절한다.
7. **표시·Excel:** 채팅에는 해석을, 같은 스냅샷의 분기 자료는 기존 캔버스 그래프와 손익계산서의 별도 ‘분기 실적(각 3개월)’ 표에 제공한다. 연간 표와 시트 8개 구조를 유지하고, 결측은 0으로 만들지 않는다.

분기 실적과 주가/PER을 함께 물으면 명시한 지표 근거도 포함한다. 이 경우 요청하지 않은 뉴스·기본 종합 리포트를 새로 생성하지 않는다. 분기 실적의 기간과 현재 시세·배수의 기준일을 혼동하지 않는다. 두 기업 **분기** 비교, 누적·전분기 자유 비교, 어닝콜·컨센서스 수집은 이번 범위에 포함하지 않는다.

## 3. 작업 중 발견하고 보완한 문제

- **소수점이 문장 끝으로 분리됐다.** 반복 검사에서 서로 다른 재무 수치가 같은 조각으로 오인됐다. 기존 presentation의 문장 구분 함수를 사용하도록 수정했다. 실제 동일 문장 반복 검사는 유지한다.
- **기간만 바꾼 질문을 회사명으로 오인했다.** ‘2024년 3분기 실적’의 연도·분기를 종목명으로 보지 않도록 제한적으로 수정했다. 공식 회사명이 있는 질의의 기업 식별은 유지한다.
- **복합 질문의 주가/PER 요청이 빠질 수 있었다.** 해당 지표를 선택·필수 근거로 보존하고, 미수집 시 필요한 부분을 수집하도록 했다. 미확보 분기 때문에 확인한 시세 답변 전체를 버리지 않는다.
- **실제 정상 문장이 쉼표 때문에 거절됐다.** ‘14.14%로, 전년 동기 대비 2.53%p 상승’의 쉼표만 검사 사본에서 정규화했다. 값·항목·단위·연도·방향 검사는 그대로다.
- **당분기 이익률 단독 표현이 거절됐다.** ‘영업이익률은 14.14%입니다’를 동일 항목의 실제 당기 값·연도와 대조하도록 했다. 다른 항목, 틀린 값, 전기 연도에 붙인 당기 값은 반례로 계속 거절한다.
- **외부 조회 실패와 자료 미확보 안내가 같았다.** 실제 고유번호 조회가 대기 상한 가까이에서 실패해 모델을 호출하지 못했다(시간 초과 추정, 당시 예외 유형 미보존). 실패 상태·조회 메시지를 보존하고, 자료 미확보와 조회 실패를 구분하도록 보완했다. 이 안내 수정은 자동 검사로 확인했으며 외부 장애가 해결됐다는 뜻은 아니다.
- **단일 지표 후속 답변에 같은 수치가 반복됐다.** 검증된 수치 문장 한 번과 의미 설명을 권장했다. 여전히 일부 반복·어색한 표현이 남아 있어 간결성 완료로 체크하지 않는다. 문체 문제만으로 정상 금융 근거를 거절하도록 바꾸지 않았다.

### 5.1 실제로 개선된 답변

사용자: **삼성전자 2025년 3분기 실적은 좋은 편이야? 세 문장으로 설명해줘.**

live3의 실제 답변:
> 삼성전자의 2025년 3분기 실적은 전년 동기 대비 매출과 영업이익이 모두 성장하며 긍정적인 흐름을 보였습니다.
> 매출은 79.1조 원에서 86.1조 원으로 8.80% 증가했으며, 영업이익은 9.2조 원에서 12.2조 원으로 32.48% 증가했습니다.
> 특히 영업이익률이 11.61%에서 14.14%로 2.53%p 상승하며 수익성이 개선된 것이 확인됩니다.

수치는 당시 OpenDART 응답을 표시용으로 반올림한 값이다. 코드의 가상 고정값이 아니며 현 시세로 사용하지 않는다. 단순 나열을 넘어 질문의 결론과 전년 동기 대비 수익성을 설명했다. 사업부·제품 가격·시장 전망을 자료 없이 덧붙이지 않았다.

live3의 분기 평가 약16.98초, 후속 약6.61초였고 후속에는 외부 재수집이 없었다. mixed의 복합 질문 약22.14초와 후속 약8.56초를 확인했다. 해당 결과에서 Excel의 두 분기 매출·영업이익·회계 기준·종목코드005930도 일치했다. 숫자 대조이며 Excel 앱 육안 검수가 아니다.
