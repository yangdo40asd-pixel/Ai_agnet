## 세부 원인과 해결

### 1. 정상 숫자 거절 (`chat_numbers`)
- 원인: 숫자 게이트(`validate_answer`)는 증감 문장·자리표시자·번호 표기 외의 숫자를 모두 거절했다. 뉴스 제목·기사 요약에 있는 "450억달러", "2026 한국품질만족지수 1위" 같은 정상 숫자도 막혔다.
- 해결(D2, `literal_numbers.py`): 인용된 원문에 단위까지 그대로 있는 금액·비율·배수·건수는 허용하고, 값이나 단위가 바뀌면 거절한다. 영업이익·매출 비교는 기존대로 구조화 사실이 필요하다.
- 대안 A(이전): 금액·% 전부 거절. 대안 B(채택): 원문 일치 허용. 되돌리려면 `literal_numbers.py`의 금액·단위 항목을 제거한다.
- 한계: 숫자가 원문에 있다는 것만 증명한다. 누구의 숫자인지는 grounding review가 판단한다.

### 2. 답변 절단과 30초 지연
- 원인 1: 문맥 4096에서 chat_answer 입력이 3363~3634토큰이라 출력 여유가 460~730토큰뿐이었다.
- 원인 2: 문법 제약 생성이 JSON을 닫은 뒤에도 공백을 내보내 max_tokens까지 가며 `finish=length`가 되었다. JSON은 완결인데 `ai_truncated`로 처리되었다.
- 해결: `LOCAL_LLM_CONTEXT` 설정 신설(기본 4096, `.env`는 8192), 서버 `--ctx-size 8192`로 재기동(VRAM 약 8.96GB, 속도 변화 없음). `local.py`가 완결된 JSON 객체이면서 `finish=length`일 때 정상 종료로 처리하고 `finish_reason_original`을 기록한다. 잘린 JSON은 계속 `ai_truncated`다.
- 남은 비용: 공백 소모로 해당 호출은 약 30초. 서버 측 공백 억제 옵션은 검증하지 못했다.

### 3·4. 후속 질문 라우팅
- 원인: `company_to_lookup`의 정규식이 질문 앞 단어를 회사명으로 취했다.
- 해결(`request.py`): 지시어 접두 제거, `그/이/저/해당 + 단어`와 "왜·어떻게·혹시…" 단독어는 회사명이 아니라고 판정. 이 경우 `route_message`가 선택된 종목(예: 005930)으로 answer를 반환한다. 테스트 `test_plan7_followup_routing.py`.

### 5. 자리표시자 오용
- 원인: 모델이 `{{ }}` 안에 금액을 넣어 존재하지 않는 evidence 키가 되었다.
- 해결: 최초 지시문과 재시도 안내(`_apply_retry_feedback`)에 키 이름만 쓰고 뉴스 수치는 원문 표기 그대로 쓰라는 규칙을 넣었다.

### 6. 기사 요약문의 숫자
- 해결: `item["excerpt"]`(`excerpt_scope == "article_excerpt"`)를 숫자 근거에 포함. 450억달러는 허용, 제공되지 않은 500억달러는 거절하는 테스트 추가.

### 7. 단순 조회 거절
- 원인: 모델이 검증기 정규식과 다른 표현("436,010.5억 원" 등)으로 썼다.
- 해결: `financial_numbers.verified_sentence(fact)`가 검증기와 같은 표시값·반올림으로 문장을 만들고, `answer_quality.model_evidence`가 이를 evidence에 넣고, `chat.py`가 `must_include_sentences`로 본문에 그대로 넣게 지시한다. 단독 금액 문장은 당기·전기 금액과 연도가 정확히 맞을 때만 `_AMOUNT`로 허용한다.
- 기존 회귀 테스트 `2025년 매출은 120.0억원입니다.`(거절 기대)는 이 허용과 충돌해서, 정확한 금액은 허용하고 값·연도가 어긋난 경우만 거절하도록 테스트를 바꿨다.
- 대안 A: 모델이 항상 `{{CMP_*}}` 자리표시자만 사용 (단순 조회가 부자연스러워 시나리오와 맞지 않음). 대안 B(채택): 검증 문장 제공 + 정확 금액 허용. 되돌리려면 `_AMOUNT` 블록과 `must_include_sentences`를 제거한다.

### 8. 원가율 원인 설명
- 해결: 원가율·판관비율도 `verified_sentence`로 제공한다. `cost_bridge_reconciled`가 참이고 변화가 있을 때만 "매출원가율은 62.01%에서 60.62%로 하락했습니다." 형식을 만든다. 실측: 삼성전자 "왜 영업이익이 매출보다 많이 늘었어?"가 원가율·판관비율 하락과 이익률 +2.19%p로 연결되어 통과했다.

### 9. "이슈" 질문의 빈 응답
- 원인: 같은 세션에서 첫 질문이 재무 중심이면 뉴스는 `not_collected`다. "최근 주요 이슈" 질문은 `request_scope`상 `all`로 분류되어 `needs_data`가 False를 반환했고, 뉴스를 수집하지 않은 채 NEWS_STATUS만 모델에 전달되었다.
- 해결: `request_scope`의 뉴스 패턴을 `뉴스|기사|공시|이슈|소식|보도`로 확장. 실측: 같은 세션에서 `FETCH_NEWS status=ok articles=10`으로 수집되고 이슈 요약이 나왔다.

### 11·12. 매수 판단 질문과 문맥 초과
- 원인: ① "지금 사도 될까?"는 범위가 `all`이어서 `needs_data`가 False였고, 재무·뉴스를 수집하지 않은 채 PER·주가만 있는 근거로 답하려 했다. ② 전체를 수집하자 `general` 모드가 모든 근거(27,535자, HISTORY 4,278자, 연도별 비교·원본 재무 사실·결측 지표 포함)를 그대로 보내 12,891토큰이 되어 서버가 거부했다(`ai_local_request`).
- 해결: `analysis_flow.needs_data`가 사도·살까·매수·매도·손절 등 판단 질문에서 수집되지 않은 뉴스·DART를 보충 조회한다. `answer_quality._fit_general_evidence`가 결측 지표 → 비교와 중복되는 원본 재무 사실 → 이전 연도 비교 → 이력 순으로 줄인다(명시 ID는 보존). 테스트 `tests/test_plan7_evidence_budget.py`.
- 실측: 입력 6,330~6,649토큰, 답변은 매출·영업이익·순이익·이익률·원가율·판관비율·주가·PER을 근거로 제시하며 매수 지시는 하지 않는다.

### 10. 이슈 카드 풀링 (D3)
- 같은 회사의 사건 미확정 기사는 적격 카드 1장이 인용 가능하다. 카드 수 한도와 확인된 사건 분리는 유지. 되돌리려면 `issues.py`의 `validate_issue_cards` pooled 블록을 삭제한다.
