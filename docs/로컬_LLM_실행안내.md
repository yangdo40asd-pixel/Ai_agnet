# 로컬 AI 실행과 복귀 안내

작성·갱신일: 2026-10-27. 실제 검수와 미완료는 루트의 `계획6_로컬LLM_통합_개발계획.md` 25절과15절 H~M 체크를 우선한다.

현재는 제한된 표본을 검수한 로컬 경로다. 과거의 타사 기사 오승인에 대해 뉴스 채택·복합 범위·단위별 관련성을 보강했고 새 Q4 복합 답변과 제한적 재작성 표본이 통과했다. 최신 전체 자동359개 통과가 모든 질문 품질 합격을 뜻하지 않는다. 기본 Groq 설정은 유지했다. 새 GPU4K 표본은 약22초였으나 이전 CPU8K 약215초와는 장치가 달라 코드만의 속도 개선으로 비교하지 않는다. GPU8K는 미검증이다.

## 기존 서비스와의 관계

기존 Groq·금융 수집·채팅·캔버스·Excel 코드를 유지하고 AI 통신 공급자만 선택한다. 로컬 모델도 실제 금융·뉴스 조회에는 인터넷이 필요하다. 앱은 모델 서버를 자동 실행하지 않으며, 실패해도 Groq로 자동 전송하지 않는다. 실제 `.env`와 기존 API 키는 이번 작업에서 변경하지 않았다.

## 모델 서버

이 PC에서 확인한 런타임은 `D:\models\runtime\llama.cpp\b11900-cuda12.4\llama-server.exe`이며, 버전은 `0.7.0-dev / 74b104c9b`다. 공식 b11900 릴리스의 CUDA 12.4 Windows 배포와 CUDA 런타임 압축파일의 SHA256을 GitHub 배포 digest와 대조했다. 재다운로드하지 않고 이 경로를 재사용한다. GGUF는 기존 Q4 파일을 사용한다. 배포본 해시 검증과 모델 자체의 원배포본 일치 여부는 구별한다.

PowerShell에서 프로젝트로 이동해 프로필 하나를 명시한다.

```powershell
cd D:\ai_agent
.\scripts\start_local_llm.ps1 -Profile gpu4k
```

- `gpu4k`: 포트 1234, Q4, 문맥 4096, GPU 사용, KV 캐시 q8. 짧은 개념·재무 비교·기본 뉴스에 대한 시험 프로필이다. 긴 후속·복합 질문의 4K 초과 사례가 있으므로 전체 서비스용으로 충분하다고 보지 않는다.
- `cpu8k`: 포트 1235, Q4, 문맥 8192, 모델 레이어 CPU 처리. 긴 업무 입력을 비교하는 진단 프로필이며 GPU 프로필보다 느리다. `-Profile cpu8k`로 선택한다. UI 지연 수용 여부는 별도 평가한다.

기존 포트에서 같은 ID·문맥의 서버가 응답하면 재사용한다. 다른 서버가 있으면 안내 후 중단한다. 서버를 자동 종료하거나 모델을 교체하지 않는다. 새로 시작한 프로세스 PID와 로그는 `.local_llm`에 기록되며 Git에서 제외한다. 종료 시 작업 관리자에서 해당 PID와 `llama-server.exe` 경로를 확인한다. 스크립트 실행 정책에 막히면 무작정 보안 설정을 바꾸지 말고 승인된 실행 방식을 사용한다.

## 공급자 선택

`.env.example`을 기존 `.env` 위에 덮어쓰지 않는다. `.env`에서 아래 항목만 추가하거나 변경한 뒤 앱을 다시 실행한다. 프로필과 주소를 맞춘다.

```dotenv
AI_PROVIDER="local"
LOCAL_LLM_BASE_URL="http://127.0.0.1:1234/v1"
LOCAL_LLM_MODEL="gemma-4-12b-q4"
LOCAL_LLM_CONNECT_TIMEOUT="5"
LOCAL_LLM_READ_TIMEOUT="180"
LOCAL_LLM_OUTPUT_MODE="schema"
LOCAL_LLM_API_KEY=""
NEWS_RELEVANCE_MODE="auto"
```

CPU 8K는 주소를 `http://127.0.0.1:1235/v1`로 바꾸고 생성 제한을 필요한 범위에서 최대 600초까지 명시한다. 긴 제한 시간이 빠른 답변을 보장하지는 않는다. 런타임 문맥·GPU 레이어·캐시는 서버 실행 옵션이며 `.env`의 모델 ID나 출력 토큰만 바꿔 늘릴 수 없다.

NEWS_RELEVANCE_MODE의 auto는 로컬에 새 정책을 적용하고 Groq는 기존 경로를 유지한다. strict는 공급자와 무관하게 새 정책을 명시 적용, standard는 이전 경로다. 로컬 검수 도구는 기본 strict로 고정해 검사한다. 새 정책은 전체 수집 뉴스를 보존하며, 답변 채택/미채택을 캔버스와 Excel의 활용 범위에 표시한다. 제목 밖 그룹 연결 자료는 확보했다고 가정하지 않는다.

앱은 기존 `start.bat`을 사용자가 직접 실행한다. Groq로 복귀하려면 `AI_PROVIDER="groq"`로 바꾸고 기존 `GROQ_API_KEY`, `GROQ_MODEL`을 사용한다. 코드 삭제나 Git 초기화는 필요 없다. 환경변수가 이미 설정된 셸에서는 그 값이 `.env`보다 우선하므로 이전 셸의 설정도 확인한다.

## 검사와 오류

외부 통신 없이 전체 회귀 검사:

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\verify_local.py
```

명시적으로 로컬 모델을 호출하는 가상 자료 검수(기록 파일 이름은 매번 새로 지정):

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\verify_local_llm.py --live --model gemma-4-12b-q4 --case financial --case basic_report --output docs\검수\로컬_새검수.json --max-requests 8
```

이 도구는 외부 연결과 Groq 생성을 막는다. 가상 자료 검수이며 실제 금융 API 성공을 뜻하지 않는다. 내부 생성·심사·재작성도 호출 예산에 포함한다. HTTP 성공만으로 품질 통과로 표시하지 않으며 원문을 사람이 읽고 평가한다. `--base-url`로 CPU 8K 주소를 명시할 수 있다.

- 연결 불가: 서버 로딩/포트 확인. 잘못된 주소를 외부 URL로 대체하지 않는다.
- 문맥·요청 오류: 서버 문맥과 요청 형식 확인. 서버가 거절하면 자료를 임의로 잘라 재전송하지 않는다.
- 출력 잘림: 결과로 사용하지 않는다. 문맥과 입력 중복, 출력 예산을 함께 확인한다.
- 형식·수치·근거 불일치: 기존 검증을 그대로 적용한다. 스키마 형식 성공과 의미 정확성은 다르다.
- 인증·모델 ID·응답 지연·서버 혼잡은 별도 오류로 안내한다. 로컬 통신 자동 재시도 및 외부 공급자 폴백은 없다. 업무 계층의 제한적 재작성은 기존 계약을 따른다.

## 유지보수 경계

`transport.py`는 명시적 공급자 선택과 공통 JSON 해석, `output_contract.py`는 스키마, `providers/groq.py`와 `providers/local.py`는 각각의 통신을 담당한다. 숫자·기간 검증, 근거 의미 심사, 출처 표시, UI 상태와 Excel은 기존 공통 계층에 둔다. 로컬 모드 예외를 업무·화면 코드마다 추가하지 않는다. JSON schema 모드는 API 제약을 쓰고 같은 스키마를 입력 본문에 중복하지 않는다. JSON 모드는 같은 계약을 입력에 명시하며 자동 전환하지 않는다.
